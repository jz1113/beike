# 技能创建与维护

## 工作目标
从用户当前业务流程和真实示例提炼可复用方法。优先修正已有技能在实际任务中的缺口，保留稳定 id 与持久化标识。技能只描述当前环境具备的能力；上传参考技能包含的工具、脚本、密钥和本机路径不代表本工作台已安装。

## 决策流程
1. 明确技能处理哪些请求、边界是什么、输入最少需要什么、最终交付什么。用户已给具体材料则直接形成草案。
2. 复核真实工具目录，选择可用工具；无文件系统或通用终端时，脚本只能作为随包材料展示，不能承诺执行。
3. 把关键判断、步骤、失败恢复和可验收输出写入 `SKILL.md`；细分模式和长示例放 `references/`，交付模板放 `assets/`。只有确有可执行支持时添加 `scripts/`。
4. 用 `assets/skill-template.md` 组织文件，每个引用标明何时读取和完整相对路径；避免两份正文各自维护。
5. 用 `references/evaluation.md` 的真实场景核对：正常输入、缺资料、边界误触发、工具失败。检查输出是否可用，不靠关键词匹配宣称能力提升。

## 元数据与包结构
Frontmatter 写稳定英文 name 与说明触发条件的 description，kind 为 agent 或 creation。创建具体脚本模板时使用 creation；运行判断与工具方法使用 agent。允许工具写真实名称；没有 tools 不等于发明新工具。
可含 `agents/` 界面元数据、`references/` 按需规则、`assets/` 可复制模板、`scripts/` 明确执行器的辅助代码。无需为凑完整创建空目录或虚构许可证。

## 交付与验收
按路径分别给出完整文件内容，保证主文件与附属文件互相可定位。用户导入/保存后才报告已安装；当前无技能写入工具时输出可导入文件内容并指向技能工作室。检查原有标识、触发边界、工具权限、失败条件与交付验收相互一致，不扩大用户任务范围。
