# 图像生成与编辑

## 模式与工具
- 新图：提炼用途、主体、画幅、构图、光影和必要文字。
- 编辑：确认源图、修改区域和保留区域，逐轮复述保留项。
- 系列：为每个资产指定独立编号、用途和差异，保持共同视觉约束。
本工作台通过 `trigger_generate` 准备首页草稿；它的回执不表示已出图。`trigger_generate_batch` 只能使用上下文已存在的 generationBatches 的 sourceId 与 entryIds，不能自行编造 id 或重写清单。

## 输入与决策
用户只要提示词时直接交付；明确要求准备生图才载入草稿。直接执行批量需有真实清单和明确的生成指令。无清单时先交付提示词，待清单形成后再提交。检查 `get_view_capabilities` 的实际支持，不把参考技能的 image_gen、Python CLI、API key 或本地文件系统能力移植为当前可用工具。

## 执行流程
1. 用一句话明确交付资产与用途，保留用户已定细节。仅补充影响结果的空缺。
2. 有参考图时按当前附件顺序定义职责。编辑写清「改变什么 / 保持什么 / 边界如何衔接」。
3. 阅读 `references/prompting.md` 的对应分支；需要版式、产品摄影或编辑示例时读 `assets/prompt-recipes.md`。
4. 组织完整提示词：场景 → 主体 → 材质细节 → 光影 → 构图 → 精确文字与限制。画面文字逐字引用并指定位置与层级。
5. 提示词代码块以 `image-prompt` 标记，每个可执行资产独立一块；解释和质检要求放块外。
6. 获得真实结果后，优先检查主体结构、商品标识、文字、构图和参考一致性。修复时一次改变一个主要变量。

## 能力限制与交付
透明底要区分视觉背景与真实 alpha；仅提示词无法保证透明通道，先核对所选渠道支持。参考数量、分辨率、画幅以当前模型配置为准；不擅自降级模型。保留原始素材和历史结果，保存与归档依赖真实界面动作，不能仅凭描述宣称完成。

交付：资产列表与参考映射、每项完整提示词、待确认的生成参数、草稿/提交/生成的实际状态。无法调用工具时仍交付可用提示词并说明阻塞点，不重复发起结果未知的计费任务。
