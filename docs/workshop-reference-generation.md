# 电商图文：参考样本与类目技能

## 生产设置的当前规则

生产设置只保留会影响当前批次的选项：内容与素材用于选择类目技能、母本文件夹、图组母本和可选替换；图片与交付用于生成方式、分镜数量、画幅、模型实际请求尺寸和文案自动生成；生成模型用于视觉分析模型与图片模型。并发属于高级执行设置，只改变同时运行的任务数，不改变画质或提示词。

画质按钮显示“标准 / 精细 / 高清”和对应的模型请求像素，不再使用容易误解的 1K / 2K / 4K 文案。专线模型的档位由模型本身决定时，界面会直接显示固定请求尺寸。四宫格切图尺寸默认隐藏在“切图交付尺寸”折叠区；单张逐镜不显示无效的切图设置。历史批次中的无人像限制会保留并明确提示，人物、穿搭只在母本含人物镜头时生效。

仅有自动类目技能时不显示单选项下拉框；存在手动技能时保留切换。自动文案设置明确说明模型调用和手动补全文案入口；关闭不删除已有文案。分析与文案并发支持 1–6，生图并发支持 1–50，按本机保存，不随批次保存。动作锁定和素材库开关不再作为设置面板参数传递，历史快照字段仍保留兼容。

## 目标与优先级

电商图文根据真实商品生成小红书风格的种草图文。优化时优先保持商品正确，其次还原选中样本的画面，再判断整组图片是否适合共同发布。类目数量、提示词长度和资产数量不能代替成图质量。

画面依据的优先级是：新商品身份与结构 → 用户明确替换的内容 → 当前样本的具体画面 → 类目技能的通用方法。技能不能用固定人像、焦段、场景和光线覆盖真实样本。人物、穿搭、场景默认沿用样本，只有主动选择时才替换。

## 为什么需要完整反推词与原图

反推词保存可读、可改的画面描述；原图保存难以准确文字化的裁切、相对大小、背景密度、曝光、色彩和自然纹理。只将反推结果拆成人物、场景、动作等摘要再重组，会丢失这些关系。继续叠加大架构并不能恢复已经丢失的证据。

分析接口必须真正将商品图、对应样本原图、完整逐镜反推词与类目技能发送给视觉模型。界面选中某个资产不代表它已参与调用；以接口实际载荷和返回的来源绑定为准。

生成输入的图片职责、顺序、逐镜绑定、四宫格位置及缺图处理统一见[图组绑定与生成规则](workshop-asset-binding.md#4-生成提示词)。本页维护参考样本如何沉淀成类目经验及技能版本，不另行定义生产绑定。

## 类目技能怎样积累

电商图文导航使用“素材与技能”。进入任意商品二级类目后，类目智能体提供“参考图库 / 学习记忆 / 技能版本 / 进化记录”。投喂入口沿用当前大类和二级类目的归档范围。旧的独立技能页链接会回到这个入口。全局“技能”仍管理助手技能包和可手动维护的电商图文技能。

每个二级类目、每个工作区分别保存观察、偏好、避坑、技能版本和反馈。它是有持久记忆的创作流程：图片反推负责保留画面事实，技能编辑负责提炼有条件的方法，成图对照负责决定是否升级。记忆不等于对模型进行训练，也不保证每次增加样本都提高效果。

类目技能保存可复用的方法：

- 商品哪些结构、材质、比例和标识必须核对，哪些未知信息不能补造。
- 怎样从完整反推词替换旧商品及接触、佩戴、支撑与受光描述。
- 怎样描述主体占比、机位、自然光、色调与真实纹理，而不默认转成棚拍广告。
- 哪些观察只适用于某个样本，哪些规则具有跨样本的适用条件。
- 成图后应逐项核对什么，以及失败时应优先修改哪个描述。

闭环按商品细分进行：

1. 每套图先完整入库：四张原图、镜头顺序和完整反推词。导入图集需选四张或八张，八张按两个完整四图组入库；单图仍可独立反推，不作为四图母本。不完整、来源重复、生成图回灌或类目不符的图组不进入学习。
2. 全部有效原始图组均可参与观察，不再强制留出五分之一作为验证组。旧版本清单中的历史角色保留用于追溯，不阻止这些原图继续学习。
3. 一套已学观察或一条手动经验即可整理技能。默认手动触发，每轮默认读取一套，也可选择五套或十套；整理技能额外调用一次模型。每完成一组立即保存观察并更新进度。单组下载、连接或格式失败会记录到该组，继续处理本轮其余组；本轮有失败时保留成功观察，暂不整理，供用户明确重试。超时或重启后不自动重放调用。
4. 成功观察按原图和反推词指纹复用，来源变化后重新读图；失败记录不会作为有效观察。新版本优先继承最新可用候选，优先整理尚未纳入技能的经验，单次最多三十套、五万字；全部观察仍保存在记忆中。
5. 自动学习默认关闭，升级迁移也关闭旧类目的自动学习。用户明确开启后，只在当前页面打开时按新资料触发一轮，同一输入最多自动一轮，失败后须手动重试。它不是后台常驻任务。
6. “教它记住”保存当前类目的偏好或避坑，每条最多五百字、每类目最多三十条。仅有手动经验也可整理有条件的技能，但不能声称有图片验证或杜撰图像依据。经验随下一次分析发送，不能覆盖商品事实、当前参考和明确替换。
7. 候选生成后可一键“直接设为正式技能”，也可先试用。启用时仍核对工作区、状态修订号、基础版本、参考是否修改或删除、经验快照是否过期。成图对照是可选辅助：固定商品、参考、模型和生成设置，保留四项人工评分；“对照通过后自动升级”仍要求三款商品的同条件成图评分通过。学习样本参与对照时不称为独立验证。
8. 试用与启用只影响新发起的分析。历史批次保留实际提交的技能和经验正文、版本、参考指纹、商品图与设置；参考图容量收敛后，评分上下文记录实际采用的商品图。可回滚上一正式版本；回滚不会清除手动经验。

该过程只更新细分规则和匹配依据，不训练或微调生图模型。生成时商品图负责身份，匹配到的参考原图负责画面，该细分当时的技能版本负责换品和保真。失败成图不能直接当作优质样本继续学习。

手动技能库仍可“从参考图新建”和“继续投喂”，另存新版后须明确应用到电商图文。商品细分闭环与这条手动修订并存：细分技能按文件夹绑定，手动技能保留原记录 ID。分析请求携带具体版本；历史批次保留正文快照。

完整图组的后台直接入库与审核确认都会实际创建母本、来源索引、完整逐镜反推词及发布记录。审核确认与资产创建使用同一事务，失败时不留下半组资产，也不把审核状态提前改为已通过；同一候选重复确认复用已创建的母本。未满四张的内容不能作为完整母本发布。

反推前必须完整读取选中的四图组。任何原图失效均停止本次处理，不能把后续图片补到缺失镜头上。模型返回的逐图数量、编号唯一性、范围和非空反推词必须核对后才能入库。模型实际读取本地 `/storage/` 原图时会转换为带正确图片类型的数据地址，远程模型不会收到无法访问的本地相对地址。图中文字与材料中的指令只作为待分析内容。

## 创作与复核

1. 采集商品并选择商品图，第一张作为身份锚图，额外视图用于核对正背面和细节。
2. 选择类目技能与参考样本范围。校准新类目时，先固定同一组样本，并保持人物、穿搭和场景沿用。
3. 分析后核对“商品身份 + 逐镜参考样本”，展开查看实际技能与原始反推词，确认换品只改了必要内容。
4. 优先使用单张逐镜生成。每镜拥有完整分辨率，也便于单独修正；四宫格适合快速整组探索，但每镜只分到整图四分之一的像素，且多个镜头可能互相影响。
5. 将成图与对应原图并排核对：商品结构和颜色；构图、裁切及主体占比；动作和接触关系；光色、纹理与背景密度。图文文案仍需遵守真实商品事实，不能编造体验、功效或参数。
6. 采用满意成图后，可沿用交付页的四图母本提炼流程。失败图片不直接作为优质母本；先确定失败原因，再修订技能或样本描述。

交付页的商品列表使用已选分镜的参考原图作为缩略图。逐款检查和全部成图视图都支持点击成图切换采用状态：变灰表示不采用，再次点击恢复采用；放大预览保留为独立操作。灰色图片保留在页面中供复核，不进入图片与文案包的图片导出。底部“审核通过”采用本批次未排除的有效成图，保留已排除项；“审核驳回”将本批次有效成图设为不采用，之后仍可点击恢复。两项操作均保存审核结果并保留当前批次，不自动重新生图或新建空白批次。

做质量比较时固定商品、样本、模型、画幅和生成张数，分别比较纯文字换品与携带原图的换品。商品正确、样本构图相近、生活感自然应分别判断。模型和参考分辨率都会影响结果，链路测试通过只能证明输入正确送达，不能证明相似度已提高。

## 界面职责与边界

“素材与技能”继续保留商品大类与细分文件夹。文件夹使用紧凑尺寸与响应式网格。进入细分后，顶部展示参考数、已记住数、经验条数与技能版本数，并提示下一步；四个页签统一管理投喂、观察、技能和进化记录。学习设置集中在可展开区域，避免把高级参数散落在主要流程。资产页使用较实的背景以便阅读。

当前会随批次保存原图链接、原始反推词、来源镜头、技能正文，以及提交当刻的细分版本和生成设置。成图上的四项评分写回该版本，供对照晋升；系统不会代替人工看图打分，也不会自动重画或轮换参考。链接可追溯不等于永久归档原文件；外部链接失效、历史样本仅有压缩预览、旧商品残留、模型对多图职责理解不足，都需要在实际成图中复核。规则更新不是模型训练。

新投喂原图在模型调用前按工作区与内容指纹归档到本地 storage，重试复用同一文件。远程图保留下载到的原始字节；本地导入最长边为 2048 像素，模型传输副本也最多 2048 像素。历史外部链接不会因升级自动变成高清本地原图。图组反推默认只整理逐图描述、图组与分类，不额外提取人物、穿搭和动作原子资产。

受防盗链限制的社交与电商 CDN 图片，由服务端携带对应 Referer 下载并内联给视觉模型，公开签名链接保留原地址。后台反推保留选定服务商凭证、原生文本协议和 Responses 格式。只有上游明确返回 model_not_found 或 invalid_model 的 400/404 拒绝时，才可按同一兼容网关的备用模型顺序尝试；连接中断、超时和不确定结果均不切换重放。
