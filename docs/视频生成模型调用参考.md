# 视频生成接入

本页合并视频能力、请求映射与任务恢复约定。下表记录当前仓库的接入配置，不代表所有渠道已完成在线生成验收。厂商规格与渠道别名分别核对，服务变更不靠静态文档推断。

## 项目请求

提交为 `POST /api/generate/video`。下面只展示业务请求体，应用鉴权、工作区及渠道凭证由前端统一请求层携带。请求前必须保存稳定的 `clientTaskId`，重试和恢复沿用该标识。

```json
{
  "model": "doubao-seedance-2.0-mini",
  "prompt": "人物保持同一身份，在明亮展厅自然转身，镜头稳定，衣服外观沿用首帧。",
  "duration": 5,
  "aspect_ratio": "16:9",
  "resolution": "720P",
  "ref_mode": "first_last_frame",
  "first_frame_image": "https://example.com/assets/start.jpg",
  "last_frame_image": "https://example.com/assets/end.jpg",
  "audio": true,
  "clientTaskId": "sales-demo-unique-id"
}
```

实际字段使用 `aspect_ratio`、`first_frame_image`、`last_frame_image`、`camera_motion`、`camera_control`，不用 `aspectRatio`、`firstFrameUrl`、`lastFrameUrl`、`cameraMotion`。全能参考使用 `images` / `videos` 数组，`ref_mode` 可为 `omni`、`first_frame`、`first_last_frame`、`text`、`edit`、`extend`，实际允许值按模型校验。

## 素材与组合限制

首帧要求一张图，首尾帧要求两张图，均不带参考视频；文生不带素材。参考模式中的一张图仍然是主体、外观或风格参考，不能自动改成首帧。编辑和延长必须有目标视频，Grok 的这两种方式限定一段视频且不带图片。

模型校验上限：Vidu 15 图、Veo 全能参考 3 图、Wan 10 图 / 5 视频、H3 9 图 / 3 视频且合计不超过 12、Grok 全能参考 14 图、可灵 Omni 7 图。Seedance 目录上限见下一节。HTTP 的 `images` / `videos` 数组另有 24 / 8 通用上限；目录上限更大不代表当前接口接受更多素材。

图片和视频各按自己的输入顺序编号，提示词先提到“图片2”不会改变实际数组排序。首尾帧与全能参考的角色不能混发；远程素材的编码、分辨率、体积及总时长仍受上游校验，尚未完成统一元数据预检。

## Seedance 请求与创作要点

- 参考图与首帧语义不同。一个 reference_image 仍然是外观、主体或风格参考；只有明确选择首帧/首尾帧时才发 first_frame / last_frame。
- 2.0 与 2.5 都露出全能参考、首帧、首尾帧、文生、编辑和延长。2.5 的首帧、首尾帧、编辑和延长跟随素材比例；普通参考模式保留选定比例。编辑发 `duration=-1` 和 `omni_reference_task_type=edit`；延长发 `extend`。提示词必须同时明确编辑或延长意图。
- 能力目录与 HTTP 校验中 2.5 图/视频上限为 30 / 10，2.0 系列为 9 / 3。素材分别按类型编号，图片1和视频1可以同时存在。排列依据上传顺序，不因在提示词中先提到图片2就交换素材位置。
- 先写主体、环境与主要动作，再写镜头、视觉风格、台词与声音。多个素材各自明确用途；不要重复堆砌相互矛盾的镜头要求。
- 2.5 长叙事可按整数秒分段，时间范围与总时长一致；2.0 使用“镜头一、镜头二”表达顺序，不能承诺精确时间轴控制。图生视频主要描述画面接下来如何变化，避免反复重述静态图片。
- 编辑写明目标素材、修改范围、保留范围。延长写后续动作与镜头，不重写原片剧情。

## 渠道路由与字段映射

分发实现见 `src/backend/internal/generate/video_endpoints.go`，字段构造由同目录各家族适配文件维护，共享端点定义在 `src/shared/domain/models/model-adapters/video/endpoints.ts`。

- Seedance 保留 `/seedance/v3/contents/generations/tasks` 与统一 `/v2/videos/generations` 候选；参考素材写 `reference_image`，首尾帧才写对应帧角色。
- 可灵按型号与方式选择 `/kling/v1/videos/text2video`、`image2video` 或 `omni-video`。Omni 参考图不标帧 type，首尾帧写 `image_list.type`；质量 mode 与端点分开。
- Wan 在千问 / DashScope 主机只走原生 `/api/v1/services/aigc/video-generation/video-synthesis`；Comfly 使用 `/qwen/api/v1/...`。其他网关按 `/wan`、`/qwen`、原生路径排列候选，保留 `{ model, input, parameters }` 和异步请求头，不改成扁平 `/v1/videos` 请求。
- Vidu 按方式使用 `text2video`、`img2video`、`start-end2video`、`reference2video`；保留渠道别名，不把所有型号重写为 Q4。
- Grok 普通生成使用 `/xai/v1/videos/generations`，编辑和延长分别为 `edits`、`extensions`。参考图写 `reference_images`，查询识别 `request_id` 与 `video.url`。
- H3 网关保留 `imageUrls`、`seconds`、`768P` / `2k`，`mode` 区分文生、首帧、首尾帧与参考。`/v1/videos` 等路径是适配器候选，不代表可以把官方 V2 的 role/content 结构直接提交给该渠道。

候选路径只在代码允许的明确拒绝条件下继续尝试，不能理解为任意失败都会换地址。5xx、网络错误和成功响应缺少任务号可能意味着已接单，须保留未知状态。渠道结果 URL 不保证长期有效，完成后按媒体保存流程处理。

## 任务回执与恢复

视频接口在付费提交前按工作区和客户端标识原子领取任务；同标识不同参数报冲突，重复请求返回原操作。响应可带 `submissionOutcome`，用于区分已接受、明确拒绝与未知提交。

没有收到上游任务号时先查 `GET /api/generate/video?taskKey=原客户端标识`；取得任务号后用 `?taskId=原任务号&model=原模型` 查询，并携带原渠道信息。未知状态不能自动另建付费任务，服务重启后也应先核对原回执。旧客户端未保存标识时，无法保证重新 POST 的跨请求防重。

电商视频的人工核对与草稿处理见[电商视频](video-sales.md)，画布素材保存见[无限画布](canvas.md)。数字人驱动使用独立的 `/api/avatar/render` 与任务接口，不与普通视频生成混用，见[模型索引](models.md#数字人驱动与语音合成)。

## 接入边界与验证

画布当前接入图片、参考视频与输出音频开关；参考音频、角色库、局部蒙版、样片模式、2K 再生成和超长视频拼接不作为已完成功能。H3 的 2K 分辨率选项不等于接入另一条付费再生成接口。

正式请求映射回归测试保留在源码旁的 `*.test.ts` / `*_test.go`；只有一次性验证脚本、截图和报告放项目外。统一检查使用 `pnpm check`。模拟测试通过只验证适配行为，不证明素材质量或渠道在线可用。
