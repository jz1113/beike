# 视频生成模型调用参考指南

本文档系统整理当前主流视频生成大模型（火山即梦 Seedance、快手可灵 Kling、阿里通义万相 Wan、生数 Vidu、MiniMax 海螺、Google Veo、OpenAI Sora、xAI Grok Video）的官方调用规范、gpt-best 网关标准对接方式、二者核心差异以及贝壳云图系统中的视频路由与任务调度逻辑。

---

## 2. 官方原生调用规范

### 2.1 快手可灵开放平台 (Kling AI)

- **官方文档**：`https://app.klingai.com/cn/dev/document-api`
- **基础端点**：
  - 文生视频：`POST https://api.klingai.com/v1/videos/text2video`
  - 图生视频：`POST https://api.klingai.com/v1/videos/image2video`
  - 全模态视频：`POST https://api.klingai.com/v1/videos/omni-video`
  - 任务状态查询：`GET https://api.klingai.com/v1/videos/text2video/{taskId}`
- **鉴权机制**：使用 AccessKey 与 SecretKey 结合当前时间戳生成带签名的短期 **JWT Token**，Header: `Authorization: Bearer <JWT_TOKEN>`。

---

### 2.2 火山引擎即梦 Seedance API

- **官方文档**：`https://www.volcengine.com/docs/82379/1520757`
- **基础端点**：
  - 提交任务：`POST https://ark.cn-beijing.volces.com/api/v3/contents/generations/tasks`
  - 查询任务：`GET https://ark.cn-beijing.volces.com/api/v3/contents/generations/tasks/{taskId}`
- **鉴权**：`Authorization: Bearer <ARK_API_KEY>`

---

### 2.3 阿里百炼通义万相 3.0 API

- **官方文档**：`https://help.aliyun.com/zh/model-studio/wan-video`
- **基础端点**：
  - 提交任务：`POST https://dashscope.aliyuncs.com/api/v1/services/aigc/video-generation/video-synthesis`
  - 查询任务：`GET https://dashscope.aliyuncs.com/api/v1/tasks/{taskId}`
- **鉴权**：Header `Authorization: Bearer <DASHSCOPE_API_KEY>`, `X-DashScope-Async: enable`

---

### 2.4 生数科技 Vidu 官方 API

- **官方文档**：`https://platform.vidu.com/docs/api`
- **基础端点**：
  - 提交任务：`POST https://api.vidu.studio/ent/v2/text2video` 或 `img2video`
  - 查询任务：`GET https://api.vidu.studio/ent/v2/tasks/{taskId}/creations`
- **鉴权**：`Authorization: Bearer <VIDU_API_KEY>`

---

### 2.5 MiniMax 官方视频 API

- **官方文档**：`https://platform.minimaxi.com/document/video_api_intro`
- **基础端点**：
  - 提交任务：`POST https://api.minimax.chat/v1/video_generation`
  - 轮询进度：`GET https://api.minimax.chat/v1/query/video_generation?task_id={taskId}`
  - 获取直链：`GET https://api.minimax.chat/v1/files/retrieve?file_id={fileId}`

## 3. 三方聚合网关（gpt-best）调用规范

gpt-best 支持两大接入流派：**统一统一格式接口 (Unified)** 与 **原厂透传格式接口 (Official Passthrough)**。

### 3.1 统一格式接口（跨厂商通用）

通过标准规范一次对接所有厂商模型，避免为每家厂商编写独立适配器：
- **提交任务端点**：`POST https://{{BASE_URL}}/v2/videos/generations`
- **查询任务端点**：`GET https://{{BASE_URL}}/v2/videos/generations/{taskId}`
- **认证**：`Authorization: Bearer {{API_KEY}}`

#### 统一提交请求体示例
```json
{
  "model": "doubao-seedance-2.5",
  "prompt": "电商运动鞋水下爆破特写，高清慢动作与微距水花飞溅，真实物理动力学",
  "images": [
    "https://example.com/shoe-hero.jpg"
  ],
  "duration": 5,
  "aspect_ratio": "16:9",
  "resolution": "720P",
  "generate_audio": true
}
```

#### 统一查询响应示例
```json
{
  "id": "task_vid_20261015_881923",
  "status": "SUCCESS",
  "progress": 100,
  "video_url": "https://filesystem.site/cdn/20261015/video_result.mp4"
}
```

---

### 3.2 官方透传模式（保留各厂商高级参数）

在 gpt-best 中，各厂商官方接口均带专有前缀，认证一律简化为网关 API Key：

1. **Seedance 即梦**：
   - 提交：`POST /seedance/v3/contents/generations/tasks`
   - 查询：`GET /seedance/v3/contents/generations/tasks/{taskId}`
2. **Kling 可灵**：
   - 提交：`POST /kling/v1/videos/{mode}`（mode 可为 `text2video`、`image2video`、`omni-video`）
   - 查询：`GET /kling/v1/videos/{mode}/{taskId}`
3. **Wan 通义万相**：
   - 千问 / DashScope 主机提交：`POST /api/v1/services/aigc/video-generation/video-synthesis`（带 Header `X-DashScope-Async: enable`），查询 `GET /api/v1/tasks/{taskId}`。请求体保持 `{ model, input, parameters }`。
   - Comfly按其文档使用 `/qwen/api/v1/...video-synthesis` 和 `/qwen/api/v1/tasks/{taskId}`。其他网关按透传顺序尝试 `/wan/api/v1/...video-synthesis`、`/qwen/api/v1/...video-synthesis`，最后才是原生 `/api/v1/...video-synthesis`。不走会改写请求体的 `/v1/videos`。
4. **Vidu 生数**：
   - 提交：`POST /vidu/v2/text2video` 或 `POST /vidu/v2/img2video`
   - 查询：`GET /vidu/v2/tasks/{taskId}/creations`
5. **Grok 视频**：
   - 提交：`POST /xai/v1/videos/generations`
   - 查询：`GET /xai/v1/videos/{taskId}`
6. **MiniMax-H3**：
   - 提交：`POST /v1/videos`（入参 `model: "MiniMax-H3"`, `seconds: "5"`, `resolution: "2k"|"768P"`, `aspect_ratio: "adaptive"|"16:9"`, `imageUrls: [...]`）
   - 查询：`GET /v1/videos/{taskId}`

## 4. 官方 vs 三方核心差异对比

- **鉴权算法复杂度**：
  - 官方：快手可灵需在本地用 SecretKey 实时签发 JWT Token（计算 HMAC-SHA256、设置 exp、nbf）；腾讯云/阿里需要签名或专用子账号 AccessKey。
  - 三方网关：统一使用一条网关 Bearer API Key，由网关节点在后端完成各厂商的协议签名。
- **音轨生成控制**：
  - 官方：各家字段不一致（可灵为 `sound: "on"|"off"`，火山为 `generate_audio: true|false`，MiniMax 则多依赖提示词注入）。
  - 三方网关：统一格式接口统一映射 `generate_audio` 布尔值字段。
- **文件下载与转存**：
  - 官方：部分模型（如 MiniMax）输出第一步返回 `file_id`，需二次调用文件接口换取下载 URL，且官方临时链接有效期短（如 24 小时）。
  - 三方网关：通常自动持久化到 CDN 或在查询接口直接返回长期可用的 `video_url`。

## 5. 贝壳云图程序集成规范

### 5.1 视频端点分发矩阵
系统在 `src/backend/internal/generate/video_endpoints.go` 与 `src/shared/domain/models/model-adapters/video/endpoints.ts` 中维护了严格的双层匹配分发：
- `seedance`：优先尝试官方透传 `/seedance/v3/contents/generations/tasks`，失败时回退统一接口 `/v2/videos/generations`。
- `kling`：根据垫图数量自动在 `text2video`、`image2video`、`omni-video` 路由间切换。
- `wan`：千问主机只走原生 `/api/v1/services/aigc/video-generation/video-synthesis`；其他网关依次尝试 `/wan`、`/qwen` 和原生路径。自动注入 `X-DashScope-Async: enable`。缺少 `input` 的 400 才换下一条地址。
- `minimax` / `MiniMax-H3`：映射 `/v1/videos` 与 `/minimax/v1/video_generation`，查询使用 `/v1/videos/{taskId}` 与 `/minimax/v1/query/video_generation?task_id={taskId}`。

### 5.2 状态轮询与持久化
前端提交视频后保存任务流水号。查询使用 `/api/generate/video?taskId=...&model=...`，并携带该模型当前渠道请求头，这样服务重启后仍能按模型家族找到查询地址。视频带货另保存提交标识，响应丢失时先查 `/api/generate/video?taskKey=...`。下载完毕后由 Go 内部的媒体下载模块转存至本地或云端资产中心。

### 5.3 多模态素材提交与时长参数规范核实（2026 最新验证）

系统前后端经过严格对齐核验，确保各模态素材与时长参数精准无误：

1. **时长范围（Durations）**：
   - `doubao-seedance-2.5`：支持 **4 ~ 30 秒** 连续时长（步长 1s）。
   - `wan3.0-video`：支持 **2 ~ 30 秒** 连续时长。
   - `sora-2-pro`：支持 **10, 15, 25 秒**。
   - `sora-2`：支持 **10, 15 秒**。
   - `kling-video-v3` / `kling-video-v3-omni`：支持 **3 ~ 15 秒**。
   - `viduq3` / `viduq3-mix` / `viduq3-turbo` / `viduq3-pro` / `viduq4-preview`：支持 **3 ~ 16 秒**。全能参考走 `reference2video`，首帧走 `img2video`，首尾帧走 `start-end2video`，文生走 `text2video`。`viduq3` 与 `viduq3-mix` 只接全能参考。
   - `MiniMax-H3`：支持 **4 ~ 15 秒**。
   - `veo3.1`：支持 **4, 6, 8 秒**。
   - `doubao-seedance-2.0-mini`：支持 **4 ~ 15 秒**。

2. **生成方式**：界面按模型露出，顺序为全能参考、首帧、首尾帧、文生，Seedance 再加编辑和延长。首尾帧与参考素材互斥。MiniMax 的「混合参考」并入全能参考；2K再生成不作为并列方式，2K 仍是 H3 的分辨率档。`viduq3` / `viduq3-mix` 只露出全能参考，Pro / Turbo 才露出全套。`omni_flash-10s` 只保留文生和首帧。Sora 只保留文生和首帧。

3. **多模态素材字段规范**：
   - **首帧图片**：传递 `first_frame_image`，只在首帧与首尾帧模式下生效。
   - **尾帧图片**：传递 `last_frame_image`，只在首尾帧模式下生效。
   - **全能参考**：Seedance 用 `reference_image`，万相用 `reference_image` / `reference_video`，Veo 用 `reference_images`，Grok 官方透传用 `reference_images` 与 `last_frame`，Vidu 用 `reference2video` 的 `images` 数组，可灵 Omni 用无 type 的 `image_list`。一张参考图不会改写成首帧。Grok 编辑走 `/xai/v1/videos/edits`，延长走 `/xai/v1/videos/extensions`。
   - **参考视频**：Seedance、万相和 MiniMax 全能参考可以带参考视频。Seedance 2.5 最多 10 个，2.0 系列最多 3 个，万相最多 5 个，H3 最多 3 个且图加视频不超过 12 个。
   - **MiniMax**：网关仍提交 `imageUrls`、`seconds` 和 `768P` / `2k`，`mode` 按方式写成 `text-to-video`、`image-to-video`、`first-last-frame`、`reference-to-video`。
   - **伴音控制**：布尔值 `audio`（或 `generate_audio`），在 Seedance、万相、可灵 Omni 等模型开启原生伴音合成。
   - **默认清晰度**：全链路统一默认 `480P`，兼顾生成速度、显存占用与低算力开销。不支持 `480P` 的模型不提供该档，默认 `720P`；若也没有 `720P`，则用该模型支持列表里的最低档。用户已选中且该模型仍支持的更高清晰度会保留。

## 视频生成请求样例

```json
{
  "description": "视频生成标准调用样例 (文生视频 / 图生视频 / 首尾帧过渡)",
  "endpoint": "/api/generate/video",
  "method": "POST",
  "headers": {
    "Content-Type": "application/json",
    "Authorization": "Bearer <API_TOKEN>"
  },
  "request": {
    "model": "doubao-seedance-2.0-mini",
    "prompt": "模特缓慢转身走入现代化室内展厅，镜头平稳推进，微风轻拂裙摆，电影级光影",
    "aspectRatio": "16:9",
    "duration": 5,
    "firstFrameUrl": "https://example.com/assets/start_frame.jpg",
    "lastFrameUrl": "https://example.com/assets/end_frame.jpg",
    "cameraMotion": "zoom_in"
  },
  "response": {
    "success": true,
    "taskId": "task_vid_20261016_882",
    "submissionOutcome": "accepted",
    "status": "IN_PROGRESS"
  },
  "pollResponse": {
    "success": true,
    "taskId": "task_vid_20261016_882",
    "status": "SUCCESS",
    "videoUrl": "https://example.com/storage/videos/20261016_882.mp4",
    "duration": 5
  }
}
```
