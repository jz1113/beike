# 助手执行机制

贝壳助手使用自建多模型运行时，Gemini 默认使用 GenerateContent、Claude 默认使用 Anthropic Messages，其他模型沿用已有协议；模型级显式配置可覆盖为 OpenAI 兼容。所有路由继续使用所选渠道的地址和密钥。并未接入官方 Codex 托管 harness，也未自动安装外部 DeepSeek agent。模型、工具、审批和运行预算分别管理。

## 多步骤任务

`update_plan` 保存本轮的简短执行清单，状态为待办、进行中、完成或受阻。完成与受阻必须附结果或原因；这属于模型提交的执行记录，不是独立验证器。简单问答无需创建计划，技能受限工具列表仍然生效。

模型尝试结束回复时，如清单仍有待办或进行中项目，运行时最多提醒两次继续处理。达到预算、仍有未完成项或受阻时，保留已有结果并把本轮标为未完成，不记录成成功。计划随工具事件持久化；跨轮继续时仍需重新核对真实状态。

## 工具与上下文

助手工具定义以 `src/shared/domain/assistant/tools/defs.ts` 为准，并导出到 `src/shared/data/assistantTools.json` 供 Go 运行时读取。图像反推、视频规格和抽帧在服务端执行；抽帧结果会作为下一轮的视觉上下文，单轮最多 20 张、合计 5MB。

选中的技能把主指令和资料目录放进系统提示，并作为本轮工具上限。请求另带 `skillCatalog`：系统提示只列出各技能的名称、用途和 id。用户点名或任务明显匹配时，主代理调用 `read_skill` 读取正文和资料路径，再用 `read_skill_file` 按路径读取细则。目录最多 16 项，正文和资料合计超过 120,000 字的后续技能只保留名称和用途。未点选技能时，读到声明了工具的技能后，后续调用收窄为这些工具的并集，并始终保留 `update_plan`、`read_skill`、`read_skill_file`、`read_tool_result`。已点选技能的工具列表不能被 `read_skill` 扩大。

请求可以带 `mcpServers`，可选 `headers` 只发给该服务，不进入模型上下文或日志。后端先完成 MCP `initialize` 与 `notifications/initialized`，保存 `Mcp-Session-Id`，再按 cursor 调用 `tools/list`。工具名形如 `mcp_服务__工具`。schema 不超过约 8KB 的工具最多直接暴露 8 个；其余用 `search_mcp_tools` 检索，并用 `load_mcp_tool` 把 schema 加入后续轮次。只有明确 `readOnlyHint` 且没有 `destructiveHint` 或 `openWorldHint` 的外部工具可以和其他只读工具并行。返回给模型的是文本；图片二进制不进入文本，小图在单轮 20 张、合计 5MB 的视觉预算内交给下一轮。生图、切页、载入工坊、改架构、图像反推和外部工具都直接执行，输入栏不再提供确认开关。`spawn_subagent` 在当前回合内启动最多 2 轮的子任务，子任务不能再拆分，也不能读取技能或调用非只读外部工具。

相同参数重复调用超过上限会拒绝该次调用，并要求调整参数或复用结果，其他工具仍可使用。总轮次、调用数、截止时间限制仍有效；不会无限重试，也不会自动重放可能计费的生成操作。

超过 12,000 字符的单条工具输出存入本轮结果库。累计工具文本超过 48,000 字符时，将更早的输出换成摘要预览与读取索引，保留最近四条。`read_tool_result` 可分页回读全文；只有开放该工具才进行这种处理。用户消息、推理字段及工具调用与结果的配对关系不被切断。这是工具文本预算，不是完整模型 token 窗口估算；结果库仅在当前轮有效。

流式工具调用按上游索引组装，保留参数与模型附加字段。空回复、缺少结束标记、长度截断及上游中止均不算成功，不执行截断的工具参数。非流式降级遵守相同结束状态检查；通道不支持工具时明确报错。

上游 Chat Completions 的 SSE 在读到每个 `reasoning_content` 或 `content` 片段时就转发给客户端：先发 `item/started`，再发 `item/agentReasoning/delta` 或 `item/agentMessage/delta`，回合文本收齐后用同一个 `itemId` 发 `item/agentReasoning/completed` 与 `item/agentMessage/completed`。完整思考文本仍会再发一次 `thinking`，供尚未接增量事件的界面使用。工具开始与结束同时发送 `item/toolCall/started`、`item/toolCall/completed` 和原有的 `tool_call`、`tool_result`；审批结束发送 `item/approval/resolved`。

OpenAI 兼容路由的网络错误、429 和 5xx 只在首个片段写出之前重试，最多 2 次，间隔按 `Retry-After` 或 400ms 起的指数退避，上限 8 秒。已经向客户端输出片段后不再重试，避免把同一段回复写两遍。Gemini、Anthropic 原生路由每次只发一次请求，错误直接返回，不静默回退兼容协议。

## Gemini 与 Claude 原生上下文

原生内容块及思考签名只在服务端保留，下一次同模型、同协议调用完整回传；签名不会拼入正文或发送至客户端。并行工具的结果先成组返回，再追加工具产生的图片。缺失参数、断流、截断或安全拦截均不能执行工具。原生图片下载使用安全出站校验，模型密钥不发给图片来源。

跨回合仅恢复已完成的最终回复原生内容，并校验工作区、会话、模型、协议、渠道地址与凭证摘要；不会从浏览器展示历史重建带签名的工具调用。上下文压缩只替换已完成的历史，不拆开本轮工具调用和结果。型号能力与档位规则见 `docs/reasoning.md`。

## Agent 提示词批量生成

生成页 Agent 和助手侧栏共用图片／视频清单。整轮回复完成后，从闭合提示词代码块提取条目；支持明确的 `image-prompt`、`video-prompt` 标签、中文编号标题、比例、像素尺寸和视频时长。普通程序代码、示例、负面词附录和未闭合代码块不进入可执行清单。同文不同交付项仍保留为独立条目；依赖其他生成结果的条目必须先补齐素材。

展开“选择并行生成”可勾选、编辑提示词、修正媒体类型和参考素材，并分别设置图片／视频模型。每项生成一份，一次最多 30 项；先校验整组选中项，再建立任务。图片编号沿用来源附件位置，视频图片／视频分别编号；首尾帧模式要求恰好两张图片。参考素材固定取原回复上下文，不读取后来输入栏里的素材。保存清单后，自然语言追问也使用保存的正文和参数。

自然语言如“把上面这些全部生成”“只生成第 2、4 项”通过 `trigger_generate_batch` 请求提交。客户端携带当前会话最近最多 8 组清单摘要（每组最多 30 项），模型只传 `sourceId` 和 `entryIds`，不重写提示词。服务端验证归属、上限与技能工具权限，并返回 `generate_batch` 客户端动作及 `operationId`。工具回执仅表示已请求，不表示已经提交或生成成功；浏览器仍校验明确的用户生成指令、来源会话、模型与素材。原 `trigger_generate` 仍只载入单张草稿。

媒体提交默认并发 3 路，可在清单内设为 1–6 路，设置保存在当前浏览器。Agent 对话使用独立串行通道，音频、深度等任务保守串行。异步视频取得上游任务 ID 后独立轮询，同步图片可重叠提交；并发限制的是提交请求，不承诺上游同时完成。删除或取消时中止对应请求，直到原请求结束才释放执行位置。

按钮、单项操作和自然语言共用来源条目提交回执。发布任务前先持久化回执；历史恢复未完成、回执损坏或存储失败时阻止新提交。重复事件、重复点击和恢复后重放不会重新提交已有条目；原任务丢失时保留“提交记录待核实”，不自动补发。Agent 结果保留在原生成会话，侧栏预先分配目标生成会话，并提供“查看本组结果”。回执保留不受普通历史自动保存开关影响；清除浏览器数据会丢失本地关联，应先核对已有任务。

视频接口在调用上游前，按工作区和客户端任务标识原子领取并保存回执；同标识不同参数返回冲突，同标识重复请求只返回原操作。`GET /api/generate/video?taskKey=...` 查询本地回执，拿到 `taskId` 后继续原任务查询。网络异常、响应丢失及提交结果未知均保留待核实，不自动重新发起计费请求。旧调用方未提供客户端标识时由服务端分配标识，无法保证丢失该标识后重新 POST 的跨请求防重，因此客户端必须持久化并复用原标识。

## DeepSeek 兼容

官方路由的思考模式移除不支持的 `tool_choice`，并将工具调用消息的空 content 规范为字符串。连续工具轮保留 `reasoning_content`，普通历史中的已保存思考内容也通过消息构建器回传；非流式回复使用相同规则。早期对话仍可能由会话记忆压缩，未保存的历史思考不能恢复。

## 验证与边界

验证脚本放在项目外，使用模拟上游覆盖执行计划续跑、工具索引、推理回传、重复调用恢复、工具结果分页与异常结束，不调用付费模型。静态检查与构建使用 `pnpm check`。真实模型的任务质量仍需实际使用评估，模拟通过不代表达到 Codex 水平。

当前内置工具主要覆盖商品采集、资产查询、文档读取、受限 JavaScript 数据处理及工作区操作，不具备通用联网搜索或任意系统终端能力。工具直接执行，执行计划不能扩大可用工具范围。
