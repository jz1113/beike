# 桌面架构改造计划

状态：第一阶段代码与本地验证已完成，Mac 应用包已构建并通过本地签名校验；第二至第五阶段尚未实施。约束：保留现有界面和数据，只做本地测试，不调用付费模型。

## 目标与边界
保留 Tauri、React、Hono、SQLite。以模块化单体逐步迁移，不引入微服务、Redis 或新的数据库。界面展示状态；本地应用服务负责业务；持久化任务引擎负责调度；网关适配器负责外部协议。Rust 保留系统权限和原生文件操作。

## 里程碑与验收
1. **工作区持久化（当前阶段）**：增加带版本的 SQLite 工作区存储、并发冲突保护和恢复界面；保存商品、选图、提示词、结果及设置。加载失败不得用空白覆盖旧记录；旧客户端写入不能覆盖新版本；恢复不触发模型调用。进行迁移、接口和前端恢复测试。
2. **持久化任务引擎**：增加 WorkflowRun、Job、JobAttempt；以事务领取任务和租约恢复，任务 ID、上游 ID、服务商配置版本、输入版本均持久化。状态含待执行、提交中、运行中、待核实、成功、失败、已取消。提交结果不确定不得自动重发；人工确认后才能新建尝试。先迁移原创工坊的一个单图任务，再迁移整条链路。新旧执行器按工作流选择，禁止双执行。
3. **统一网关**：服务商 ID + 原始模型 ID 作为唯一模型标识；模型目录、能力、凭证引用、提交/查询/错误分类统一放服务端。前端只提交模型引用。迁移旧固定分流配置；已提交任务保持原配置；配置删除需检查在途任务。
4. **状态与媒体性能**：数据库为任务事实来源，Query 为读缓存，Zustand 只保留交互状态；事件通知配合断线后的增量查询。移除不必要的 Query→Zustand 双写；逐步卸载隐藏页面；缩略图、虚拟列表、后台切图和流式导出。
5. **发布与维护**：按模块清理被替代代码；源码、用户数据和构建缓存独立；Mac 包验证与本地签名自动化；导出诊断信息时隐藏密钥。保留迁移备份与可恢复旧版本的数据副本。

## 性能验收方法
在同一台 Mac、同一数据集记录冷启动/热切页耗时、长列表长任务、批量期间内存峰值、后台队列时延、ZIP 导出总耗时。使用 20 款商品×4 张图的本地模拟数据及大资产列表；分别记录本地时间和网关时间。先采基线，再比较改造结果，不能用测试数量替代流畅度测量。

## 第一阶段的明确限制
工作区快照不是完整后台执行器。应用退出后的本地调度暂不继续；恢复只显示旧任务和已完成结果，未确认完成的任务保留待核实提示，不自动重新收费生成。快照自动保存有短暂合并窗口，关闭窗口前应确认显示“已保存”。密钥不属于工作区数据。

## 回滚
新增表不改旧业务表；数据库升级使用现有启动前备份机制。旧版本可能拒绝较新迁移记录，因此回滚必须恢复对应备份，不能直接以旧程序打开新库。每个阶段完成类型检查、相关测试及全量回归后再切换默认执行器。
