# 电商图文：图组绑定与生成规则

## 产品目标

输入真实商品图片，生成小红书风格的种草图片与配套文案。类目技能提供商品保真与换品方法，参考样本提供具体画面；分析与生图都使用原图，不将完整反推词压缩成通用场景摘要。操作与优化依据见 [workshop-reference-generation.md](workshop-reference-generation.md)。

已确认：未手动锁定图组时，按每款商品自动匹配完整图组，并可选择全部图组、含人物镜头或全组无人物。默认保留母本逐镜构图、动作、场景及出镜范围；人物、穿搭、场景允许显式整组替换。不得将“未选择替换项”解释为随机抽取资产。

## 资产职责与优先级

1. 商品图：新商品身份、品牌、型号、颜色和外观的依据。母本中的旧商品描述不能作为新商品事实。
2. 图组母本：提供四镜顺序、主体占比、动作/摆放、机位、光线和逐镜出镜范围。
3. 人物资产：仅替换人物镜头中的人物描述，不能将静物或仅手部镜头变成人像。
4. 穿搭资产：仅替换人物镜头中的穿搭，不影响商品本身；服饰类商品需要兼容性检查。
5. 场景资产：用户显式选择后整组覆盖场景及其光照描述，原场景文本不再追加进提示词。
6. 商品拍摄规范：约束商品展示，不应改写母本镜头，也不能用通用首饰规则覆盖手机等商品。

“图组原场景/原人物”是继承内容，不应伪造为资产库中另一个资产 ID。图组与拍摄架构各自可以自动匹配；人物、穿搭和场景的默认值为“沿用母本”。

## 用户流程

### 1. 入库

解构图片，保留来源图片索引、逐镜结构、出镜类型和可替换项。完整四图组才能进入自动匹配；残组可查看但不可当完整母本执行。图组归类应描述主体商品，避免用桌垫、帽子等道具误判商品类目。

四图母本另存商品细分，它与 `category` 记录的画面风格独立。资产库按「商品大类 → 商品细分」文件夹浏览，可新建、改名并在编辑母组时调整归属；未确定细分的母组进入「待分类」。手机数码沿用手机本体、手机壳、耳机和平板四个内置细分；自建细分优先按已保存的文件夹关键词及别名规则与商品标题/类目匹配，未配置时再按名称和已有兼容规则核对，前端候选检查与服务端生产使用同源规则。珠宝细分还核对戒指、项链、耳饰等佩戴部位；部位规则为空时按可见商品判断，不强加身体部位。缺少可核对规则或名称的自建细分不进入轮换。旧母本仅在商品主体证据明确时回填分类；仍未分类但证据一致的沿用原有匹配。已归入手机文件夹的母本即使画面中出现保护壳，也继续作为手机构图母本使用；手机壳商品只从镜头明确以壳为主体的母本中选择。耳机、平板等不同主体与文件夹冲突时，该组暂停轮换和手动固定，须在资产库复核归属；系统不会擅自移动用户的母组。

商品类目与文件夹的管理入口统一放在“素材与技能”。电商图文导航只保留创作工作台和素材与技能，不再提供独立“商品类目”或“技能”页。旧 `tab=categories`、`tab=recipes` 链接及恢复的同名界面状态会映射到 `prompt_assets`。文件夹右键菜单或目录中的“分类规则”按钮打开“文件夹分类规则”对话框；高级折叠区提供批量导入和旧缓存预览迁入，手机端也可通过按钮进入。规则只允许修改当前工作区自有文件夹，官方资产库文件夹可查看但不可修改。关闭旧入口不会删除原有文件夹、服务器规则或浏览器本地规则；旧缓存须先预览、核对归属后再显式迁入，使用事务导入接口并保留原缓存，不能直接按名称或重合关键词覆盖服务器文件夹规则。

导入反推可分别指定商品大类和二级文件夹。从二级文件夹内打开导入时默认沿用当前位置，切换大类清空原二级选择；自动识别大类时不锁定子文件夹。二级选项与资产库当前名称和删除状态一致，选择具体文件夹后，本批待反推图组统一归档到该位置；选择自动匹配时按每组内容判断，无法确认的保留在该大类的待分类。手动归档不会改写图组实际商品证据，生产时继续核对文件夹与内容是否相符。队列恢复保留选择，服务端在反推前和正式入库时检查父子归属；审核候选保存该位置，重复反推或确认入库时不得进入已删除文件夹。

图片采集完成并选图后，点击「后台反推」将整个队列提交给服务器；提交确认后窗口自动收起，关闭窗口、切换页面或刷新不会停止服务器队列。全局任务通知持续展示进度，完成、部分失败和错误保留至用户关闭，可查看原队列并手动导出记录。停止只取消尚未派发的图集，已经提交的请求继续收尾。网络回包未确认时按同一任务编号查询或重新提交，不创建重复任务；服务器重启遗留任务标记为「需核对」，不得自动重放付费调用。模型密钥仅用于执行时的内存凭证，不进入持久化任务数据。本地图片先保存为受工作区保护的素材引用。

出镜类型分为人物、仅手部、纯静物。has_human 表示需要人物/穿搭资产的人像镜头；仅手部通过 hand_held_only 单独标记。

### 2. 商品与选图

选定本次生产商品和身份锚图。当前实现使用第一张选中的商品图作为每镜生图锚图，最多再带三张商品视图核对结构；分析可读取全部已选商品图。界面应明确主图身份，不能把“勾选多图”宣传为逐镜自动选择最佳正反面。

### 3. 绑定规则

生产设置包含三部分：
- 拍摄架构：可以按商品类目逐款自动匹配，也可以为批次手动指定。只从当前可见架构中选择；名称和正文品类冲突、手动架构与手机或珠宝商品明显错配、或自动模式找不到相符架构时，分析前阻止执行并说明原因。
- 母本文件夹：沿用资产库的「商品大类 → 子文件夹」结构与当前名称，可按商品自动匹配，也可限定到某个大类或子文件夹。文件夹计数只包含已发布完整四图母本；已归档文件夹不提供选择。指定范围后，自动轮换与手动固定都只能从范围内选择，并继续执行逐商品品类、细分及出镜检查；不会因为指定了手机文件夹就把手机壳商品强行套入。范围按当前批次自动保存，改名即时同步；已删除或与新拍摄架构不符的旧选择需要重新选择，分析前会阻止执行。从资产库载入固定母组会恢复为自动文件夹范围，避免被上次的范围误拦截。
- 图组来源：按商品自动轮换（全部图组、含人物镜头、全组无人物），或为当前批次固定一个完整图组。固定图组选择器支持按永久组号搜索，并以封面图识别母本；有人物指四镜中至少一镜明确有人像；全组无人物允许仅手部镜头；出镜类型待判定的图组只参与全部图组轮换。
- 可选替换：人物、穿搭、场景。提供“全部沿用母本”恢复入口。

固定图组显示四镜摘要。无人物镜头的图组不应用人物/穿搭绑定，并提示原因。全部图组轮换中，人物/穿搭替换只作用于实际选中的有人物母版；若每款都需要人像，应选“含人物镜头”。拍摄架构选定后，设置区只展示对应商品大类的归档量及二级文件夹分布；尚未采集商品时不把大类库存标为可用数，也不提供固定组选择。商品进入批次后，再按商品标题、采集类目、细分文件夹、母组内容和出镜范围显示逐款候选数。手动固定也必须通过相同的商品匹配，设置区与分析前检查使用共享规则拦截跨类目、跨细分或文件夹与内容冲突；服务端重新检查所选母组的归属、可见性与原图完整性。自动选择按批次内已保存的实际母组排除已用候选，并结合商品位置分配；没有未用候选时尽量避免重复当前商品的上一组。候选池只有一组时允许重复。当前不承诺跨批次服务端预留或严格的并发无重复轮换。

自定义替换从资产库中选择已发布且可用于生产的场景、人物和穿搭。选择器展示封面、编号、人群和当前可选数量，并可跳至对应资产分类管理；待分类的人物或穿搭不能载入电商图文替换。人物与穿搭可锁定单项或按选定范围轮换；双槽都替换时必须使用性别、年龄段兼容的资产，只替换一槽时另一槽沿用母本逐镜描述，仅拦截能确认的冲突。分析前检查选项和可兼容组合，前端将兼容组合解析为具体 ID，服务端重新核对这些资产的可见性与发布状态。无人物或出镜类型待判定的母本不会应用人物、穿搭替换；界面保留并标明这些暂不生效的选择，切回含人物母本可恢复。无人像模式只提供全组无人物的图组候选，原来锁定的不兼容图组保留提示供用户纠正。自动轮换全部图组时，界面按当前商品类目候选说明有多少商品可能用到人物替换，不能把全库库存当成实际生效数。从资产库重新载入一个图组时，场景、人物、穿搭和动作恢复为沿用新母本，避免继承上一个图组的替换。

### 4. 生成提示词

前端沿用统一候选规则解析实际母组与人物穿搭组合，冻结具体 ID 后提交。后端从当前工作区重新读取母组、完整反推词、四张来源原图、类目技能与有效替换资产，核对可见性、发布状态、文件夹与原图完整性。视觉模型以完整反推词为起点做最小换品，商品图核对新商品，原图逐镜核对构图。服务端校验输出数量和顺序，并锁定已明确的出镜类型及来源；缺失分镜不会自动填充通用镜头。前端直接保留这些提示词，不追加通用人像或首饰模板。

手机正面镜头将“机身”与“屏显”分开：机身比例、边框、开孔、颜色和实体标识以新商品参考图为准；亮屏画面的题材、主色与氛围从所选母本的对应镜头反推词中提取，并为新商品重新设计。不得复制商品垫图的假 UI、乱码、通知或母本旧手机的具体界面；母本熄屏沿用熄屏，屏显主题不可靠时采用协调的简洁无字画面或自然熄屏。该规则不作用于手机壳等配件。

四镜使用原组结构；八镜在原四镜后追加派生镜头，并保留来源关系。八镜是扩展，不是八张原图的忠实还原。

四宫格的整图画幅、质量与切图尺寸分开设置。默认按模型实际整图四等分；也可为每张分镜指定常用比例或 1–4096 的整数像素宽高。比例不同会居中裁切边缘，再等比缩放，不拉伸商品；放大像素不会增加原图细节。设置随批次保存，任务另存当次整图尺寸与交付尺寸。改变切图尺寸会区分新任务；恢复原任务仍使用已保存尺寸。单镜重画按模型支持的画布生成后裁切为原分镜交付尺寸，上传失败可核对原任务恢复，无须重复生图。ZIP 与表格使用最终切图链接。

网关返回的实际像素与请求画布不一致时，先验证原图可解码，再按任务保存的交付尺寸居中裁切并等比缩放，不将已生成图片标记为生图失败。四宫格按实际原图拆分并输出保存的分镜尺寸。刷新后自动核对当前批次中保留任务标识的待恢复结果，持续最多六分钟；只查询原任务并完成尺寸处理、上传，不重新提交模型。核对沿用任务保存的模型与对应服务商，已成功的服务端回执优先复用；超时或素材读取失败后仍可手动「核对原任务」。

当前生图输入为“商品身份图 + 对应样本原图 + 换品提示词”。传输顺序为最多四张商品视图、构图参考图、可选正脸锚图，提示词中的图片编号与实际顺序一致。先为对应样本和明确需要的正脸锚图保留槽位，再按模型容量缩减额外商品视图；三图上限模型在单镜下使用一至两张商品图加本镜样本。若连商品主图与必要参考也无法同时容纳，提交前提示改用容量更大的模型；四宫格容量不足时提示改用单张逐镜，不丢弃样本或错写图片编号。单镜仅带本镜样本，四宫格带四张样本并绑定各格位置；派生镜头使用对应来源样本。样本中的旧商品、标识与水印不应迁入成图；这一要求必须结合实际成图复核，不能仅凭链路测试宣称已经完全解决。旧的图组分析没有原图绑定时，需要重新分析后生图；历史成图仍然保留。

### 5. 修改、重试与追溯

修改图组/替换资产/商品图，使受影响的旧分镜失效；正在进行的旧分析结果不得回写。仅修改画幅、质量、生成模型时复用已确认提示词。失败重试应使用当次已确认的绑定，不能重新随机匹配。

每款商品应展示实际使用图组、匹配方式与替换项；每镜应展示商品锚图、提示词和来源镜头。已经生成的图片保留历史版本，避免配置改变后失去可追溯性。

### 6. 满意成图衍生母本

生成时按母本结构和当前商品形成新分镜与成图；这些结果只属于当前批次。连续四镜均生成成功并由用户逐张标记“采用”后，可从交付页发起新母本提炼。八镜结果按每四镜一组分别判断。

提炼先保存为待确认候选，展示四张来源图与可复用架构摘要。用户确认后才创建并发布一个完整四图母本，记录来源母本；取消确认不会进入轮询。衍生流程只沉淀图组母本，不自动扩张人物、穿搭、场景等原子资产。重复提交同一四图来源应复用候选或已发布结果。

资产库图组卡片显示永久组号与真实标题，使用当前工作区图组库永久分配的“组 1、组 2…”编号，默认按组号升序展示。工作区图组库包含本工作区与共享官方图组；其它工作区、历史单图和无图组结构的旧反推记录不参与编号。现有图组按迁移时的画廊顺序一次性编号；后续新增图组按创建顺序递增。筛选、排序、收藏、使用和删除都不改变已分配的编号，删除后留下的号码不复用。固定图组选择器、衍生来源和生产结果均显示同一个组号，便于辨认和核对轮换；实际绑定仍使用资产 ID。工作区库号保存在 FullPromptLibraryNumber，FullPromptAsset.displayNumber 保留为历史全库编号，不直接用于界面。数据库中的 groupIndex 是图集内部序号，只用于还原来源图片关系，不作为库号。原图 #1/#5 表示图集中的图片位置，不表示所用母本。迁移仅修正历史记录中同时匹配资产 ID 与旧号的明确绑定字段；已删除母本或未匹配的记录保留原值。旧分析记录或来源母本已删除且缺少组号时，以稳定的 #R 资产编号兜底追溯。JSON 备份重新导入的资产分配新组号，避免与现有编号冲突。

点击图组卡片的封面、组名或“查看图组与分镜”，统一打开四图母版预览。图片按 `sourceImageIndices` 对应到原图集中的位置，并与逐镜提示词按镜头编号对齐；缺图时保留镜头位置，不能把后续图片向前挪。右侧可切换整组提示词、单镜提示词和母本信息，保留修改标签与载入电商图文入口；预览使用与画廊、生产设置一致的永久组号。新投喂保留本地归档原图；历史压缩预览图的分辨率不会因放大布局而恢复。

资产库 JSON 备份从 v3 起一并保存商品品类、图集和资产审核记录；再导入时重建图集与资产的关联，保留四镜索引、逐镜提示词、审核状态和衍生母本来源。旧版 v1/v2 备份未包含图集及审核记录，导入时按原图集 ID 和资产来源信息重建图集，并提示审核状态无法恢复；无法映射的旧商品品类会清空并给出汇总提示。重复导入会复用已恢复的图集，但资产仍按新增处理。

电商图文生成成果的批量下载包按商品建立“组号---商品 ID-生成标题”目录；尚未生成文案标题时省略末尾标题。每个商品目录只放当前四镜的“图1”至“图4”图片和仅含生成正文、按段落排版的“文案.txt”。包内汇总表及独立表格导出使用同一列顺序：商品名称、商品类目、商品id、生成图片链接1～4、标题、文案、对应生成的提示词资产分组组名。镜头链接按镜头号对应，缺失镜头留空，不拿其他镜头补位；分组名使用永久组号，不使用图集内部的 groupIndex。

## 当前实现范围

- 自动匹配（含出镜类型筛选）与手动固定图组；完整性校验；模型 product_sentence 响应支持。
- 四图母本商品二级分类可筛选、编辑并参与自动匹配；手动固定时同样执行大类、细分和母组内容匹配。
- 默认继承母本，显式替换单项；非人物镜头不读取人物/穿搭锁定项。
- 完整逐镜反推词最小换品路径，保留来源原图和原始反推词；服务端锁定出镜类型。
- 生图提交同时携带商品身份图与对应样本原图；确认页展示实际样本与使用的技能快照。
- 绑定区分层、四镜摘要、沿用母本入口、人物替换适用范围说明。
- 从资产库载入新绑定后使旧分镜失效，避免继续生成旧提示词。

## 当前限制

- 分析前已有候选检查与固定图组摘要，但没有独立只读 resolve 接口完整返回每款商品的选择原因和绑定快照；不能把界面候选数当作服务端预留结果。
- 已保存逐镜来源图、原反推词、来源组和技能内容，尚未完整保存所有替换资产版本、匹配原因及服务端配置版本；不承诺跨批次原子预留或并发无重复轮换。
- 自建细分仍依赖文件夹关键词、别名、名称与兼容规则的文本匹配；未确认商品细分时的冲突、场景与动作接触关系、服饰商品与穿搭兼容性仍需人工复核。
- 图组预览已经实现，显示与生产一致的组号和镜头位置；历史压缩预览不能恢复为高清原图。实际素材可读性、换品质量及配置修改后的重试，应按下列验收标准核对当前部署版本。

## 验收标准

- 手机静物图组不能自动注入模特、私服、首饰佩戴和 85mm 人像机位。
- 仅手部镜头允许手部，禁止添加人脸；不出现“禁止手部”的冲突文本。
- 未替换场景时保留逐镜实际场景；替换场景时不残留原场景和旧光照。
- 更换人物/穿搭不改变静物和仅手部镜头的出镜类型。
- UI 显示的组、替换项、商品图与最终请求一致。
- 未匹配到完整图组时在调用视觉模型前失败；单个失败不计为分析成功。
- 结果可以追溯到绑定配置；旧配置的迟到响应不得覆盖新配置。

新建批次默认单张逐镜，并沿用上一批次的视觉模型、生图模型、画幅、质量、生成方式及切图设置；商品、图组锁定与执行状态重新开始。选完商品图直接进入分镜分析，电商图文技能在生产设置中选择，无需额外确认架构弹窗。自动类目技能入口只保留一个。

Stage 1 支持本地创建商品，Stage 2 的“添加本地商品”可继续向当前批次添加：填写名称、类目，选择或拖入同一商品的 JPG/PNG/WebP 图片（最多八张），图片先上传到配置的素材存储，取得持久地址后再创建商品，默认勾选前两张；刷新可恢复。本地存储按当前工作区归档。链接采集完成默认勾选首张有效静态主图，动图不进入选图池。选图仍由用户核对，系统不能仅凭链接判定尺寸未知图片是否为售后长图或干净主图。

升级迁移只根据完整四镜正文的明确出镜事实修正 model_shot 误标，并按至少两镜“主体”段落的明确证据修正标准手机文件夹中的配件图组；仅恢复确有这些图组需要的内置细分文件夹，不恢复无关归档类目。仅在细节描述中提到手机壳不足以将手机母本改为手机壳。迁移前自动备份；不删除原图、反推词、历史批次或手动经验。
