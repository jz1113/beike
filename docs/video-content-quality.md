# 电商视频质量与类目接入

## 依据与适用范围

本规范把用户提供的电商视频优质、普通、低质标准转为当前产品的创作和人工验收口径。用户提供的京东案例页面未在本次形成可听看的成片证据，因此不引用其具体镜头、声音或效果作为整改依据，也不将这份材料称为已核实的最新平台规则。

运行规则的唯一维护源是 `src/shared/domain/assistant/skills/packages/fashion-video-sales/references/content-quality.md`；本文件说明产品含义、服饰用法与后续类目接入条件。当前只接入服饰、鞋、包，本文的其他类目为后续接入规范，不表示功能已经上线。

## 质量判断顺序

“良好的声画 + 必要的信息 + 可口的叙事”是三个需共同满足的条件；好人设可增强信任与记忆，但不能抵消任一条件缺失。不要把它改造成一个可以互相抵分的总分。

1. 先找低质问题。违法违规、不适内容、搬运、虚假或过度营销、无主题、过时信息，以及严重制作瑕疵，都需定位整改。普通和优质不应包含未解决的低质问题。
2. 再判断信息增益。专业度与信息量可择其所长，但都要真实、与主题相关并有实际用途；并非所有视频都要专家出镜或讲大量参数。
3. 再判断叙事。内容简单清楚也可构成风格；趣味、情绪、审美、场景、钩子、稀缺和热点是可选择的手段，无需全选。钩子有承诺就必须兑现。
4. 最后判断人设加分。讲解视角清楚、表达有记忆点即可；可信来自证据与边界，不能靠服装、场景或虚构职业背书。

声画合格却只展示外观、报属性或反复说好用好看，属于普通内容。优质目标要让观众具体知道“这件东西对我眼下的选择有什么帮助”。还没有成片或未完整听看时，只能说方案符合创作要求，成片保持待验证。

## 当前服饰规则的整改重点

原有技能对保色、商品结构、人物一致性、物理动作、正常景别和口型已有细致约束。它们是保质基础，但无法单独证明内容有用。当前规则据此补充以下要求：

- **从报属性转向解释选择**：先确定受众、需求和一个主要问题，再选支持它的已知事实。颜色与领型不因被念出来就有增益，要说明当前搭配或结构取舍。每项信息在规划中关联原始依据、展示方式与结论边界。
- **从生活摆拍转向有目的的展示**：地点、姿态与衣物操作应增加信息。保留自然交流和必要动作，不用收包、喝咖啡、换场景填时间，也不要求每句话都有手势。
- **从自然开场转向明确看点**：前5秒内让人看懂商品与选择问题。可以先给当前搭配结果，也可以直接说一个具体观察；不用强制设问、夸张、制造焦虑或单独留5秒前言。
- **从字数合格转向信息有效**：现有5–6汉字/秒仍是容量建议；每句话是否解释主线更重要。不用加快语速、重复卖点或堆语气词达到字数。两条不同事实支撑一个问题即可，不等于要讲两个故事。
- **从口型检查扩展到完整声音质量**：检查普通话、吐字、人声音量稳定、噪声与失真，并确认讲到的部位和动作同时可见。逐段实际听看，不能用转写或波形替代口型和音质判断。
- **从生成起点扩展到首帧与封面用途**：生成参考静帧用于建立拍摄起点，发布封面优先选人工确认后的成片画面。主体暗、过曝、关键部位裁断或不可辨时先整改。不能把生成照片称为真实拍摄，也不额外自动调用封面生成。
- **从拿到视频转向有依据的验收**：完整听看后记录具体问题时间范围、影响、整改对象和复核状态。任务成功、静帧确认与程序计时通过不能替代内容评级。

例如，只有原图确认黑色圆领上衣、胸前浅色贴布，且本片确实搭配浅色裤子时，“黑色、圆领、胸前贴布，很高级很百搭”仍主要是外观清单。可改为围绕“这件黑上衣怎么搭出颜色呼应”展开，展示贴布与裤子的颜色关系，解释为何此处少加一个颜色。这个例子只说明信息组织方式；它不是任何SKU的事实，不是统一开场，更不能据此宣称显瘦、显白或适合所有身形。

服装优先解释轮廓、开合和搭配关系；鞋优先解释有证据的鞋型、鞋口、系带或穿脱结构；包优先解释有原图依据的开口、肩带和取物路径。生成上身、走路或装包画面不能证明合身、舒适、耐走、防滑、容量或承重。

## 证据与AI演示边界

将来源与结论的能力分开：

- 原始商品图支持其中清楚可见的颜色、结构和标识，不能证明触感、性能、耐久或使用经历。
- 可核实的商品资料支持其明确记载的参数和适用条件，不自动等于讲解者实测，效果或测试结论仍需对应依据与适用范围。
- 真实演示素材只支持其中实际发生、可看清的操作和结果；测试条件、型号和样品不匹配时不能直接泛化。
- 生成画面用于展示已知外观、构图和搭配方案，不能反过来作为新增商品事实的来源，也不能证明真人使用体验。

这意味着全AI流程可以改善表现、清晰度和解释能力，但不能凭提示词补足“实拍”“真实体验”或“专家资质”。发布渠道若要求实拍，必须准备真实素材并核对渠道要求；生成内容的标识方式也要按实际渠道确认。不能承诺仅靠拟真画面通过平台质量评定。

价格不展示、无字幕、同一SKU、正常距离展示等继续是当前服饰工作流的具体约定。它们不是用户提供的全部平台标准，不应扩大为所有类目的通用硬规则。

## 后续类目技能的组成

保持“通用质量规则 + 类目证据规则 + 内容模式 + 模型执行约束”四部分：通用层定义质量与验收；类目层定义哪些信息可以说、用什么证明；内容模式决定如何讲；执行层负责参考职责、画面、声音、时长与提交恢复。不要把四部分各复制一套进代码内置提示词。

当前通用规则随服饰包发布，第二个类目实际接入时再提取共用编译输入并分别装入技能包，版本摘要覆盖实际执行内容。各类目按阶段接收所需章节；生图不接收口播时间轴，视频模型不接收人工审核教程。保留现有任务回执和历史结果，规则更新不自动触发付费重生成。

新类目至少说明：

1. 目标消费者的主要选择问题，及解决它所需的最少事实。
2. 每项事实的允许来源、适用型号或规格、未知项及冲突处理方式。
3. 外观展示、使用说明、真实体验和性能测试的边界，以及不足证据时可采用的较窄主题。
4. 合理的演示场景、可完成动作、应展示的部位和必要的声音；景别由任务决定，不照搬服饰的中景约束。
5. 核心禁用宣称与需要额外证据的说法，避免用自动生成的动作结果证明功效。
6. 人工成片验收项目、问题时间点记录方式，以及失败后返回事实、脚本、素材或定稿的路径。

具体类目可按以下方向建立规则，不机械套同一带货模板：

- **家居收纳、日用工具**：围绕放置、取用、清理或操作路径解释。尺寸、安装条件、承重和兼容性需要资料或实际演示；AI画面中“放得下”不能证明真实尺寸匹配。
- **数码配件、小家电**：围绕型号兼容、操作步骤和适用场景解释。接口、功率、协议和功能来自对应型号资料；续航、性能、噪声或效果比较需真实依据。局部操作可用必要近景，不延用服饰的默认景别。
- **食品、饮品**：围绕可核实的配料、规格、食用方式及储存条件解释。口味、口感和个人偏好须有真实体验，生成切面、拉丝、试吃动作不能证明风味或成分，更不扩写成健康效果。
- **美妆、个护、清洁用品**：围绕包装结构、资料支持的使用方法和明确适用条件解释。体验、效果及前后对比需要匹配产品与条件的依据；不生成假实测、假效果对比或虚构专业身份。

## 验证与后续产品能力

当前已实现的是规则编译、阶段注入、版本失效与已有流程检查；质量分类与问题记录是人工执行规范，尚未新增自动评分接口、审核看板、真实体验素材采集或发布系统。

后续产品能力应优先补齐证据来源记录、开头看点与展示的对应关系、成片人工问题标记、实际封面选择；需要真实体验的类目再接入对应素材流程。每项能力都先保存事实和来源，再考虑自动检测，不能用模型自评的总分替代证据。

验证规则效果时固定SKU、时长、画幅、模型与参考图，先只改脚本或提示词，再单独比较素材变化。人工比较声画缺陷、信息是否有用、开头承诺是否兑现和人设是否可信；记录实际观察与未验证项。付费生成只在已有授权范围内执行，不能把技能升级或测试通过当成实际成片改善的证明。
