# 电商视频工作台

电商视频工作台提供「视频制作」与「资产库」两个主入口。资产库侧栏按「素材资产」与「创作配置」分组：素材包括动作素材、人物资产、场景资产与声音资产四类；提示词管理归入创作配置。首次进入资产库默认打开动作素材，切回资产库时保留上次打开的分类；制作页的脚本入口直达动作素材，人物、场景与声音的添加入口分别直达对应资产分类。当前商品在视频制作页采集、上传和设置，当前草稿保存在本机。页面入口及网址标识继续使用 `video_sales`。

视频制作沿用浅色与深色灰阶主题、48px 顶部导航及「商品资料 → 分镜脚本 → 生成成片」流程。桌面左侧商品区初始宽度为 420px，可拖拽调整；右侧文字阅读宽度最大 936px。图库与文字区各自滚动，商品资料阶段左右底部操作栏均为 72px，正文保留底部留白。商品卡只展示缩略图、两行省略的名称及规格/分类/受众摘要；「商品设置」使用居中弹窗，名称支持多行编辑，品类与适用人群并排展示，修改即时生效。SKU 等商品详情与来源折叠收纳，更新采集与换商品链接集中放在商品操作区，清空商品独立放在底部并沿用确认流程；窄屏或低高度窗口只滚动弹窗正文，保持关闭和完成操作可见。图库默认三列，空间不足时两列，统一 4:5 缩略图并完整显示原比例图片。

- **① 商品资料**：左侧选择参考图，右侧固定为「商品卖点」工作区，标题旁显示待识别、待提炼、已提炼或处理进度。识别引导、可编辑文字和最终卖点从同一位置开始；提炼完成后原文收纳到默认折叠的「查看识别原文」。参考图与 OCR 图片独立保存，原始识别文字、用户修订及最终卖点分别保留。右侧底栏从左到右为模型选择、OCR 识别、文字样式的「跳过，进入分镜」和主按钮「提炼卖点」；模型与 OCR 组成工具组，窄栏分两行显示。没有识别图片时 OCR 位置提供「添加详情图」，全部识别完成后显示禁用的「OCR 已识别」，新增图片后可继续识别。提炼成功后后两项变为「重新提炼」和主按钮「下一步：分镜脚本」。任务说明只在工作区显示。
- **② 分镜脚本**：移除分镜预览监视器舞台，全宽仅保留高密度内联分镜编辑表格（`# / 商品图 / 时间·镜头 / 画面动作 / 台词 / 字幕 / 姿态 / ⋯`）。单元格直接编辑画面动作、口播台词（实时显示字数、语速及 `> 4.5 字/秒` 偏快橙色预警）与 SRT 字幕草稿，表情与段落衔接收纳在行尾 `⋯` 展开区；点击商品图或姿态格弹出更换选单（支持 `正 / 斜 / 侧 / 俯 / 仰` 多机位预览与唤起开源姿态图鉴 `AtlasHubDrawer`）。制作设置与改写操作全部沉入底部 56px `.sales-actionbar`：左侧提供 5 个向上展开设置选单（`脚本`、`人物`［按当前商品适用人群自动过滤推荐置顶，不匹配人群折叠在「展开其他人群」中］、`场景`、`声音`、`动作参考`），右侧提供改写模型选择、`按商品重新改写` 与 `下一步：生成成片 →`。
- **③ 生成成片**：左中为中性暗色视频播放舞台（支持生成进度反馈与「原视频 / 最终成片」切换下载），右栏（380px）依次集中展示 3 列紧凑引用素材核对网格（含更换人物/场景侧滑抽屉入口）与声音配乐/字幕下载（含 `StudioAudioPlayer` 试听与本地配乐上传），底部 56px `.sales-actionbar` 左侧放置视频模型参数（向上展开选单）与生成/导入视频按钮，右侧放置合成成片与导出操作。
- 编辑标签切换只改变可见内容，保留制作控制器、草稿及进行中的请求。任务期间进度和停止等待入口跨编辑标签可见，暂时锁定换商品、选图、返回首页、进入模型设置及切换到资产库；任务结束或停止等待后恢复。从资产库返回视频制作时刷新脚本和素材目录，清理已删除资产的失效引用，保留上传文件、分镜编辑与生成结果；资源读取与生成任务的取消和状态独立管理。

## 提示词管理

「资产库 → 创作配置 → 提示词管理」集中展示六套当前提示词，复用资产侧栏，在提示词管理下按「商品文案（1）、分镜脚本（3）、资产补图（2）」分组：商品卖点提炼、参考视频拆解、外部分镜规整、商品分镜改编，以及人物、场景补图的 `persona-grid`、`scene-grid` 九宫格模板。右侧为全高编辑区，保存操作固定在底部。旧的六套单视角模板已移除，管理页面也过滤旧服务返回的单视角模板；升级迁移仅清理这些旧模板的工作区覆盖词，其他环节提示词不受影响。每个环节可复制、编辑和保存，保存即更新系统在当前工作区使用的提示词。九宫格编辑区提示保留 3×3 等分、视角顺序、无边框和无文字要求，保证裁切后正确对应各视角。页面区分已生效、未保存和待核对状态，不提供默认内容查看或恢复入口；编辑时可对照已保存内容或撤销未保存修改。切换环节、资产分类或返回视频制作均保留未保存的提示词，资产侧栏显示「未保存」提醒；离开整个工作台时确认是否放弃修改。每次进入提示词管理时重新读取后台当前内容，保留未保存的编辑；读取失败、保存失败或版本冲突时标记为待核对，重新读取后才允许保存，不把旧缓存显示为已生效。保存回执需与提交的环节和正文一致，迟到的读取结果不能覆盖后续保存。提示词保存遇到短暂数据库写锁会进行有上限、可取消的重试，每次重试重新核对版本，不覆盖另一页面已保存的内容。

保存到当前工作区后，下一次执行对应环节使用保存的提示词，刷新、重新打开或重启后端后仍可读取。明确保存的内容即使与内置初始模板相同，也会持久保留，不随后续内置模板更新而改变。已有文案、脚本、分镜和已提交的图片任务继续保留；要按新规则生成结果，需要手动再次执行。人物与场景九宫格任务在首次提交时固定提示词及版本，继续查询原任务、重试裁切或恢复缺失裁片不会重新生成。

提示词是完整的当前环节指令，修改文案和脚本模板时需保留对应 JSON 输出结构，修改九宫格模板时需保留图片布局与视角顺序；商品资料、原视频或视角参考图在执行时另行加入。脚本规整有独立的完整模板，修改脚本拆解模板不会同时覆盖规整模板。服务端仍校验模型返回内容；最终视频提示词根据当前选择自动组装，不在分镜选择与生成成片页展示编辑器。

参考画风通过「拆解 → 外部规整（自由文本导入时）→ 商品改编 → 最终组装」连续传递。拆解在现有 `visualSpec.styleSummary / lighting / cameraFeel` 中记录色调、反差、纹理与柔化程度、光向、曝光、机位俯仰、主体占比和空间纵深，动作段记录幅度、快慢、停顿、视线、材质随动与衔接。未知内容留空或写入 `review`，不以通用「电影感、高清写实、自然柔光」补齐。外部规整保留这些具体信息，区分原片观察和未核实建议；合法 JSON 直接导入时仍需确认这些内容已在原 JSON 中提供。

商品改编接收完整 `visualSpec` 及每段 `subject / scene / expression / transition`，并独立输出适配后的 `expression` 和 `transition`，不依赖动作正文顺带保留表情。表情按视线、眼睑、嘴唇嘴角、头部变化的起止与回落描述，区分垂眼与闭眼、轻微张唇与连续说话式口型；手型保留掌心朝向、腕部弯折与伸指状态。衔接记录末姿势和表情如何延续，结束段不新增原片没有的前倾、挤眼或大笑；生成时长补足部分延续末姿势与自然呼吸。无口播不等于全程紧闭嘴唇，也不把每个动作配成持续甜笑。

商品、人物和场景资产负责实体外观与布局，参考脚本负责摄影基线；场景资产的默认光线不能覆盖已记录的参考光线。一镜到底仅约束不切镜，不自动添加推拉、摇移或跟拍，多动作段保留所属真实镜头边界。更换商品时保留人体动作节奏，按新商品结构调整材质响应，例如短袖不复制长袖甩动。原视频引用可提供动作与摄影画风，深度素材只提供几何与动作，不能提供色彩、光线、肤质或细微表情时序。模型清晰度等设置不能补回缺失的表情，也不在提示词中编造焦距、ISO或表情强度等控制值。既有脚本和改编结果继续保留，需重新执行相应环节才能补齐新信息；旧改编缺少独立表情或衔接时，不把可能残留旧场景的原字段直接拼回。

妆容与表演分开：眉眼、唇色、肤色及妆容浓淡以当前人物原图为准，人物九宫格只补充角度与身形，清晰的派生脸图不能覆盖原图妆容或加重磨皮。表情字段只描述视线与肌肉变化，普通眨眼闭合后复睁，垂眼不等于长闭眼；仅按明确记录保留持续闭眼，不因微笑额外挤眼。拆解将原房间、门墙和家具留在 `scene`，不写成必须复制的摄影属性；改编替换所有旧地点，最终每段显式引用所选场景图，光线关系适配该空间，不为复制原背景而重建另一个房间。旧脚本含美肤滤镜等观察时，不把它当作加重妆容或磨皮的指令。

`GET /api/sales/prompts` 读取各环节当前内容与版本；`PUT /api/sales/prompts/{id}` 使用版本核对保存，页面始终提交编辑后的完整文本。当前内容持久化于 `SalesPromptOverride` 表并按工作区隔离；尚无保存记录的环节使用内置初始模板。接口保留历史 `defaultPrompt`、`customized` 响应字段和 `prompt: null` 重置行为以兼容旧客户端，当前页面不使用这些默认版本功能。脚本分析缓存及中断恢复均按实际提示词版本区分，不仅按视频地址复用；历史记录继续保留。已经完成但待保存的分析只重试保存，已有脚本仅补深度时也不重新调用分析模型。摄影、场景、主体、动作、表情和衔接字段提供错误类型、null 或超长文本时明确报错，动作和动作模板均为空时不能保存，不在规整时静默丢弃；不合规缓存不参与自动复用。提示词读取禁用缓存，读取或存储故障明确停止执行，不退回内置初始模板；外部拆解的「复制分析提示词」读取同一当前工作区版本。

## 操作流程

1. 左侧粘贴京东、淘宝、天猫、1688 或拼多多商品链接；京东也支持商品编号。也可上传或拖入本地图片、文件夹补充素材。图片区顶部仅保留「商品图片 + 数量 / 上传 / 收起」和「全部 / 主图 / 详情 / 已选」两行；SKU 图片仍可从全部中查看。
2. **点击左侧图片主体**选择或取消参考图，选中采用细描边并按点击顺序编号。右下角放大按钮只打开预览，不改变选择。左底栏统一显示「已选 X 张参考图」、批量操作和次级「确认选择」；确认保存当前选择并保持展开，标题处的收起按钮独立控制侧栏。批量菜单提供「将当前分类全部选为参考图」「清空参考图选择」「识别当前分类文字」及失效图片重试。分类批量选择和识别仅作用于当前分类，清空参考图不改变 OCR 来源。
3. **从左侧拖图片到右侧编辑区**，仅加入识别输入，不改变参考图选择。右侧「添加详情图」默认添加前 6 张尚未加入的详情图，不足时按实际数量添加；无详情图则使用可用商品图，无候选时打开本地上传。空态高度约 200px，显示添加入口、默认数量说明并支持本地图片或文件夹拖放。实际识别图片及数量在横向队列中展示，可增删、单张识别或重试；重复加入不会产生重复项。
4. 将文字图片加入后，点击底部「识别文字」统一处理。识别时仍可在左侧点选参考图；采集、上传和识别队列暂时锁定，避免更换正在处理的来源。可停止后继续，或只重试失败图片；成功结果不重复处理。服务繁忙或未安装环境会停止本批次并保留已完成结果。
5. 「商品卖点」按图片编号展示可编辑识别文字，并提供「补充商品文字」供直接输入或粘贴。原始 OCR 返回可单独展开查看，用户修订与原文分别保留。提炼使用当前队列中的有效文字及补充内容；其他尚未识别图片不阻塞已有文字，重新识别失败后仍可使用保留的有效文字。失效来源、空白文字和队列外历史文字不进入当前提炼。原文工具栏可复制汇总文字，保留不同数字与百分比。
6. 右底栏「生成设置」集中展示当前模型和现有参数；主按钮依次为「添加详情图」「识别文字」「提炼卖点」「下一步：分镜脚本」。有可用文字即可提炼，包括纯文字输入。识别或提炼时主按钮显示进度并禁止重复提交，保留对应停止入口。提炼完成后「重新提炼」为文字操作；未提炼时可通过「跳过，进入分镜」继续。参考图数量只在左底栏显示，识别数量只在右侧工作区显示。
7. 队列缩略图关闭按钮移出单张，「清空识别图片」移出全部；只改变本次识别与提炼范围，参考图选择、识别记录和文字编辑继续保留。重新加入时复用已有结果，已移出队列的历史原文仍可回看，但不用于当前提炼。左侧商品区常驻商品名称、品类与适用人群，页首右侧显示本机保存状态。

商品资料主界面不再展示重复的商品属性表单或长段流程说明。右侧只保留一套工作区，正文最后一行可完整滚动到底栏上方。已采集资料、旧草稿及兼容的已确认文字继续保留，当前操作不删除原始素材、服务端缓存或数据库。洗护图形等非文字内容不做语义解释；数字、成分比例和说明文字需人工核对。

## 多模态卖点提炼

模型选择沿用主页的渠道、模型家族和版本菜单，直接展示在右下角底栏，向上展开，切换模型在当前页完成。显式选择保存在 `summaryModel`，切换标签、刷新、重新采集或更换商品时继续使用该选择；不在商品草稿中另存 API Key。

「商品卖点」共用一个阅读宽度受限的内容区，按处理阶段展示识别引导、可编辑文字或最终卖点。提炼成功后展示最终卖点，原文收纳在默认折叠的「查看识别原文」中，两份内容各自保存。卖点提炼为可选步骤，没有明确卖点或只做商品展示时可通过底部「跳过，进入分镜」继续，不发起卖点模型调用。

在底栏选择模型并点击「提炼卖点」。结合左侧参考图、当前队列有效的修订文字、对应原图和补充商品文字，生成一句话概括、带来源的商品特点/消费者买点/自然表达、推荐文案及必要的冲突/待确认项。纯文字输入可直接提炼；只有参考图时仍需先识别或补充文字，空白识别结果不作为输入。OCR 入口独立于提炼按钮，补充文字或已有提炼结果时仍可识别新增图片；识别期间该入口原位变为「停止识别」。

提炼按所选模型渠道计费，手动触发；所选图片和资料会发送到该渠道。免费本地 OCR 不变。不会发送整库图片，不使用已移出队列的历史文字。最多使用 16 张不同原图、合计 20 MiB，单张核对文字最多 40000 字、合计最多 60000 字；超限明确提示，不静默截断。原图读取沿用 OCR 的工作区隔离及公网下载校验。

最终卖点以条目和短段落展示，一句话概括、各条标题/依据/表达以及推荐文案均可直接编辑；可复制全部或单独复制推荐文案，来源链接可打开对应原图。OCR 原文不随结果编辑而改变。草稿允许编辑期间暂时清空字段并原样恢复，保留字段长度及结构约束，接口对新生成结果仍进行完整校验。技能要求列明图文冲突，未核实内容不用于成稿；保留数字、主体与局部成分、使用限制，不将低比例成分写成主材，不虚构实测、亲肤或显瘦等承诺。语义约束由模型执行，使用前仍需复核。

界面先展示买家的购买理由，再列对应商品事实和来源。成稿由同一次模型请求从已提炼买点中选最有说服力的 2—3 点展开，有效买点少则少写；`copyPointIndexes` 记录所选编号，服务端检查存在性、重复和数量。先说具体吸引点，再说明与日常选购、搭配或使用的关系，减少参数罗列和泛化广告句。买家视角可以表达选购偏好，不编造买过、用过或实测经历。写作规则与技能一并传给模型，不增加二次润色请求；规则更新后保留旧稿及手动编辑，提示重新提炼。

更改选图、OCR 文字或采集资料后提示上次结果已过期。重新提炼由用户触发，处理期间保留当前文字或已有结果，按钮显示加载状态；成功后才更新结果并默认显示最终卖点。失败、停止和返回内容不完整时保留已有内容并提供底部重试，不自动重试、不自动换模型。接口校验结构与来源编号，不用本地套话替代失败结果。更换商品和清空草稿会清除提炼结果，原始素材与服务端数据保留。结果、条目修改及用户编辑的推荐文案跟随当前草稿保存在本机。

## 交互与等待

卖点请求按「输入及来源校验 → 读取/转换原图 → 按所选渠道协议调用模型 → JSON 与来源校验 → 常见无依据效果检查 → 保存」处理。模型看到明确的 `product-meta`、`ocr-N` 和 `image-N` 来源 ID；商品参考图与文字来源图标注用途，同图的文字和原图不视为两份实测证据。原始 skill 文件保持完整，应用约束补充成稿检查，规则版本同时覆盖 skill、输出契约和检查版本；规则更新后旧结果保留并提示重新提炼。

检查会拦截常见的无依据版型保证、耐用承诺、身体修饰效果，以及资料未提供的服装触感、重量和保暖说法；这不能替代全部语义和图文核对。禁止模型擅自选择冲突资料的一方用于成稿，不把字段简写与完整成分表自动当作冲突。「使用与养护」单独展示模型提炼及已识别标签中的明确限制，如手洗温度、不可干洗；这些限制不包装成卖点。

失败响应区分图片转换、模型鉴权/路由/参数/配额、渠道服务、超时、返回 JSON 和成稿检查阶段，并提供请求编号及上游状态。服务日志仅记录模型、协议、阶段、数量与脱敏错误，不记录 API Key、原图数据或整份商品正文。不自动换协议、重试或重放付费请求。

上游 403 若包含 `Verify your account`，提示渠道账号需要验证；这类问题需由渠道账号所有者处理，不能当作模型不支持图片、skill 未加载或普通密钥填写错误。保留当前资料和上次结果，验证后由用户重新提交。

选图和编辑立即更新页面；草稿按 250 毫秒合并，在浏览器空闲时写盘，最长空闲等待 1 秒。页面隐藏、离开工作区及清空商品时刷新最后一份待保存草稿，存储失败保留当前页内容及待保存快照。图片库使用远程缩略图、按需加载和异步解码，缩略图失败时回退原图；大图预览、OCR 和模型输入继续使用原始图片来源。

本机保存失败时，页首提供「重试保存」，无需另改内容即可重新写入最后的完整草稿。通过页首返回首页前先尝试保存，失败则留在当前页；关闭或刷新浏览器时也先刷新待保存草稿，仅在仍有未保存内容时请求浏览器提示。浏览器是否展示提示由其自身策略决定。采集或上传期间仍接收独立的制作参数和模型偏好更新，避免后台返回或编辑被静默丢弃。

原图不可用或重新识别失败时，已有 OCR 原文和编辑内容继续展示。不可用原图不发送给模型；重新识别失败但原图仍可用时，可使用保留的修订文字继续提炼或再次重试。识别成功但没有文字的图片显示「未识别到文字」，可直接补充文字或留空跳过。

OCR 批次仍按顺序执行，可停止、继续及只重试失败项。卖点提炼单独管理取消状态，等待模型时保留当前内容并允许回看原文或结果，编辑和识别操作暂时锁定；选图或其他来源更新会立即取消旧提炼，不让晚到结果覆盖新资料。采集、上传或重新识别时同样停止旧提炼。模型入口不自动发起付费调用，重复点击不并发提交。服务端最多同时读取 3 张模型输入图片，去重并保持来源顺序，单张读取失败会取消其余读取，不发送缺图请求。

新增 Go 接口后，运行中的本地 API 需要更新到相应构建；旧服务的 404 会明确提示重启服务，不显示无法判断的「接口不存在」。

## 参考脚本库（P0 结构化拆解与入库）

页首「资产库」左侧「素材资产」分组依次包含动作素材、人物资产、场景资产和声音资产四类，默认打开动作素材，「创作配置」分组提供提示词管理。当前商品的采集、上传、品类与人群设置统一在「视频制作」中完成，当前草稿保存在本机。动作素材统一承载脚本、同源视频及独立动作素材。脚本与同源视频作为一组素材管理，负责上传、预览、编辑、归类和删除资产。动作、人物、场景与声音库内不显示当前商品的已选状态，不提供选用、应用到分镜或底部前往视频制作的操作，统一在「视频制作」中选用。来回切换保留已选商品图、品类与人群标注、视角标签、OCR 汇总、卖点结果、已选脚本及资产绑定方案。

1. **视频联合导入**：
   - 点击一次同时开始脚本分析与深度动作视频转换（默认动作捕捉风格、标准质量）。转换提交前保留恢复标识，刷新或取消等待后继续查询原任务，避免重复提交。失败时仅处理未完成项，已完成脚本和视频不重跑。分析完成但保存失败时在本机保留正文，重试仅补保存。可先保留脚本、稍后处理深度，也可暂存未完成导入并继续导入其他视频；恢复时显式继续未完成步骤。
   - 旧脚本的原视频可能已被历史版本清理，可以重新关联原视频，或手动选用素材库中已有的深度动作视频；不按名称猜测对应关系。
   - **上传参考视频自动拆解**：通过 `POST /api/sales/script-video` 上传本地 MP4、MOV 或 WebM（≤64 MiB）至当前工作区存储，由 `ffprobe` 读取真实时长、画面比例与音轨状态；再调用 `POST /api/sales/script-analysis`（需 Gemini 原生视频协议模型，单视频直传 ≤16 MiB）输出结构化草稿，并用内置 `ffmpeg` 自动抽取每段中间时刻预览帧覆写模型猜测时长与比例。相同视频哈希与提示词版本优先复用已有拆解记录。
   - **外部对话粘贴导入**：通过 `GET /api/sales/script-analysis/prompt` 一键复制当前工作区已保存的拆解提示词，在外部多模态对话分析后粘贴返回文本至 `POST /api/sales/script-normalize`。若粘贴内容已是合法脚本 JSON，直接校验载入且不触发模型调用；若为自由文本分镜，则按所选文本模型规整为标准结构化模板，并可选关联本地参考视频补齐实测规格与抽帧。
2. **结构化模板与防串货剥离**：
   - 采用 `shots`（真实切镜）+ `beats`（镜内推拉/动作段）双层时间轴，兼容一镜到底连续运镜与多机位切镜剪辑。
   - 模板固定保存全局视觉基调 `visualSpec`、后续资产需求槽位 `assetSlots`（商品视角、人物双锚点、场景空间与动线、口播/旁白语速与 BGM 情绪）、去商品化动作模板 `actionTemplate`、可复用台词句式 `linePattern` 以及原片专属剥离清单 `sourceExclusions`（原商品、品牌招牌、原模特外貌、私人配饰、未证实话术）。
3. **分镜文稿阅读与确认入库**：
   - 脚本分镜库按卡片实际宽度紧凑排列，卡片间距为 16px；仅使用关联深度视频的首帧作为封面，展示标题、时长与入库状态。无深度视频或预览失败时显示占位，不使用原视频或原片分镜预览图回退。点击封面进入按时间顺序排版的分镜文稿，分类、归档和删除收纳到封面操作菜单。每段展开画面风格、主体、动作描述、镜头变化、眼神表情，已记录的场景光线与衔接方式同屏展示，下方直接提供完整中文即梦生成提示词。支持复制单段提示词或完整分镜文稿，保留十分之一秒精度。
   - 一镜到底按镜内动作段连续编号，页面明确提示这些段落并非真实切镜。中文提示词由现有可复用字段即时组装，保留商品占位、动作顺序、声音模式与时间；不会自动把原片台词、字幕或原始观察记录写进生成提示词，原片剥离词在提示词中统一替换。选用脚本后再结合当前商品与素材生成最终提示词。
   - 参考视频用于探测时长、画幅、音轨及抽取分镜预览关键帧，并保留在当前工作区。导入时一次启动脚本分析与深度视频转换，两路结果独立保存；脚本完成即可核对，深度转换尚未完成或失败不影响脚本使用。原视频、深度任务回执与深度视频结果关联到同一脚本记录。
   - 查看脚本时收起资产分类导航，阅读区使用完整工作台宽度。1024px 及以上采用左侧分镜目录与「脚本设定」、右侧分镜正文的布局，侧栏可拖拽调宽，左右独立滚动；目录随当前阅读段落高亮，点击只滚动正文。窄屏使用单列滚动、横向分镜目录，设定默认收起，可按需展开。概览与首段从顶部连续展示，「深度动作视频」默认折叠，展开只预览深度视频并维护关联，不展示原视频或原音轨入口；原视频数据保留用于补做深度。设定包含脚本标题、自建分类与风格、剪辑结构、声音模式、出镜形式和画面风格与光线；总时长沿用拆解结果并在顶部展示，不提供独立修改入口；不展示原片专属剥离清单、资产槽位汇总和提示词骨架预览。分镜文稿直接以结构化拆解卡片与中文即梦生成提示词展示，不再提供逐段分镜与时间折叠编辑器。
   - 若 `actionTemplate` 或全局风格残留 `sourceExclusions` 中的原片专属词，界面即时告警并支持一键替换为 `{{商品}}` 占位；通过时间轴校验且无原片词残留后方可确认入库（状态由 `draft` 升为 `verified`）。确认入库只保存资产并返回脚本库，不自动选用或跳转到视频制作。
   - 入库模板保存在 SQLite `SalesReferenceScript`（`GET/POST /api/sales/scripts`、`PATCH/DELETE /api/sales/scripts/{id}`）；既有脚本可直接按新文稿形式打开。在视频制作中选用的 `selectedScriptId` 随当前商品草稿持久化。
   - 取消分析、关闭或切换草稿后，迟到结果不覆盖当前草稿；连续点击保存只提交一次。保存期间的新编辑继续保留，需重新保存后再确认入库。保存失败保留关联视频与已完成转换；旧列表响应与使用统计回执不覆盖最新的删除或归类结果。
   - 未保存脚本返回列表、切换功能或离开工作台前提示确认，刷新或关闭浏览器时提示未保存内容；保存期间锁定返回与跨页操作。在视频制作中选用脚本时，使用次数独立递增，不覆盖同时保存的正文或归类。分析和导入均按实测视频时长复核时间轴，校验失败保留原片供重试；取消分析同时停止后续预览抽帧。

## 资产匹配、提示词组装与配乐成片

人物和场景绑定只使用明确选中的资产，选中资产失效时保留选择标识并提示重新选择，不静默换成推荐第一项；已选场景没有可用主图时停止生成，补充场景图后继续。自定义人物与人物库互斥：只上传人脸或主体图也不会补入旧人物库的另一张图；重新选人或智能匹配会切回所选库人物并解除自定义引用。商品图只提供商品结构和材质，其中的模特、场景人物及原视频人物不参与出镜身份；摄影风格迁移不改变所选人物的五官和辨识特征。

自动改编记录当时的提示词版本及商品、当前有效最终卖点（含条目和推荐文案编辑）、人物、场景、参考脚本内容来源。生成前实时核对改编提示词版本，版本缺失、变化或读取失败时停止提交；修改最终卖点、更换人物或有效场景、修改同一脚本的动作、表情、衔接等内容后保留既有分镜和手工编辑，但须重新适配，避免旧描述覆盖新选择。仅调整分辨率、配乐等无关设置不触发重新适配；纯商品脚本不检查无用的人物字段，无自动来源记录的手工分镜保持兼容。需要人物出镜的脚本若实际引用中没有人物图，会在提交前阻止生成，不以商品模特或动作视频代替人物参考。仅有人脸图时可锁定脸部，但身形没有独立参考；纯商品脚本不因残留人物选择而新增模特。

选用脚本后，动作参考仅有「仅按脚本」与「脚本＋深度视频」两种方式，默认仅按脚本；两种方式都使用所选商品、人物和场景图片。深度视频须关联当前脚本，实际进入最终引用清单与视频模型请求，并与分镜时间对应；未就绪时不可选择。制作设置不再提供原参考视频和逐镜手动动作，旧记录中的这些模式读取时回到仅按脚本，保留已有分镜编辑、绑定数据和产出媒体。切换脚本会重置关联引用与过期生成结果。

脚本与视频统一归入素材库。脚本库的分类与拍摄风格由用户自行创建，不预置商品类目或拍摄风格目录。动作素材通过左侧商品类目导航筛选分类，顶部统一提供风格筛选、搜索、刷新与「管理分类与风格」入口。管理窗口按「素材分类 / 拍摄风格」切换单列表，分别保留名称搜索；列表展示名称、当前列表使用组数和行内重命名与更多操作，同源脚本与关联视频只计一组，归档脚本不计入当前列表。分类用于归档动作与脚本，风格标记分镜脚本的拍摄形式。新建入口展开独立表单，拦截同类型重名；新增、改名和移除即时保存，失败保留输入，保存期间阻止重复提交和提前关闭。移除经行内确认，只解除对应归属，不删除素材。宽屏左侧切换管理类型、右侧编辑，窄屏改为顶部切换；列表独立滚动，标题与完成操作保持可见。风格筛选菜单适配深浅主题并支持搜索；选项数量保留其他筛选条件计算，脚本与关联视频只计一组。列表显示筛选后数量与总数，已选条件可单独移除或一键清除。人物、场景与声音资产同样区分库为空、筛选无结果和读取失败；刷新时保留已显示素材。名称最多 40 字，同一工作区内同类型名称不能重复；分类和风格独立维护，风格可跨分类使用。

新脚本可以先入库、后归类。卡片直接展示分类与风格，点击后在居中弹窗同时选择两项，再点击「保存归类」；保存失败保留选择，取消不改动脚本。详情「脚本设定」也可归类。审核状态只显示在脚本卡片上，不混入分类目录；顶部不再提供分类和素材类型下拉，默认统一展示脚本、独立视频与动作图片。风格筛选只提供「全部风格」和自建风格，展开后显示当前条件下的数量（包括 0）；未设置风格的素材正常包含在「全部风格」中。分类管理的重命名按钮保持可见，移除收纳到更多操作并保留右键入口。每条脚本可归属一个分类和一个风格，未指定时显示「未分类 / 未设风格」。原有脚本的内容与历史业务元数据保留，不将固定业务标签自动创建为用户目录。商品匹配仍使用独立的商品适用信息，不根据用户自定义名称猜测商品范围。

人物与场景资产页提供「批量导入」，支持多选或拖入图片，每批最多 50 张、单张最多 20 MB，每张创建一个独立资产并归入当前分类。名称按全库中「人物N / 场景N」最大已有编号顺延。资产库的动作、人物、场景、人声与 BGM 均按名称自然正序显示，自定义名称同样参与排序，名称中的数字按数值升序，例如「室内1、室内2、室内10」。普通导入逐张上传并保存，失败项可重试，已成功项不重复入库；重试保留已上传图片，并先核对丢失保存回执的资产。可勾选「导入后后台补全九宫格」，选择一次生图模型，为每张导入图片提交独立后台任务，生成完成后自动保存。

`POST /api/sales/asset-view-jobs` 保存基础资产及持久化任务，`GET /api/sales/asset-view-jobs` 返回当前工作区进度。后台任务独立执行，资产页显示排队、生图、裁切、入库和完成状态，完成后刷新资产。裁切或保存失败可「继续处理原任务」，沿用固定提示词、模型、原任务编号和已生成原图，不重新付费生图。服务重启后将中断任务明确标出，用户可继续处理；模型凭据不写入任务记录，恢复时重新读取原渠道配置。已受理的任务以工作区及请求标识去重，保存回执丢失时同标识核对原任务。上传主图或单视角仍显示上传状态；生成期间主图和已有手动视角保持原样，只有空位被补齐。新接口需运行更新后的 Go API，启动时执行任务表迁移。

动作资产在素材库中预览、编辑、归类或转换为深度素材，保存后可跨商品复用；库内不读取当前脚本、不选择动作段，也不显示已应用状态。声音集中展示人声音色与背景音乐；卡片仅展示类型、名称和 BGM 时长，试听按钮位于封面中央，播放时可暂停，不显示描述、标签与底部波形栏。点击名称打开详情，可编辑或删除资产。声音编辑与删除只有在数据库写入成功后才返回成功，保存失败保留界面草稿；音色标识可更新，描述和标签可显式清空。配乐编辑只保存情绪标签，BPM 与授权说明仅作展示，不混入标签。人物、场景、动作、音色及背景音乐均在视频制作的对应设置中选用，自有配乐在生成成片页上传并绑定当前商品；动作按分镜段绑定时保留其他段和已编辑台词。无人物占位记录不作为出镜人物展示。

声音资产页的「导入 BGM」支持批量选择音频（每批最多 30 首、单首最多 32 MiB），或试听并选择内置的 5 段 12 秒短配乐入库。内置配乐只在手动导入后计入当前工作区资产。批量导入逐首显示进度与结果，失败后可只重试失败项，已成功项目不重复导入。可保留原长度或从开头截取 10、15、30 秒；服务端检测实际音轨与时长，短于目标的素材保留到结尾，不填充成虚假时长。背景音乐可按 15 秒内、15–30 秒、30 秒以上筛选，卡片与成片配乐选择显示时长。

参考视频上传区提供「保存参考音频」，可试听原视频声音，填写名称并保存整段或指定起点的 10、15、30 秒片段到声音资产库。保存的是原音轨，包含已有的人声与环境声，不执行人声分离；无音轨视频明确提示失败。上传音频与视频原音轨保留各自来源说明，不自动标为免版权。素材库保存后可在生成成片页选用，合成按成片时长循环或截取配乐并淡出。

`GET /api/sales/studio-bgms/builtin` 读取可选短配乐；`POST /api/sales/studio-bgms/import` 接收 `audioUrl`、`videoUrl`、`builtinId` 三种来源中的一种，以及可选名称、起点与截取时长。导入最长 600 秒；本地来源核对工作区，远程来源沿用公网媒体读取限制，重复请求复用同来源、同截取范围的已保存资产。新接口需运行更新后的 Go API。

素材目录查询失败返回错误并提供重试，不伪装成空库；视频制作仅在目录成功刷新后清理失效引用，读取失败时保留现有素材绑定。画外旁白模式下，当前台词尚无有效配音时不能提交最终混音。

制作区按「商品资料 → 分镜脚本 → 生成成片」组织。已选商品图后进入分镜或成片页会收起选图区，可随时从左侧迷你轨一键展开。分镜页采用全宽内联表格集中展示时间、景别、用图与姿态，画面动作、台词与字幕直接单元格编辑，主体、表情与衔接收纳在行尾「细节」。文本按内容自动增高，当前有效的脚本动作与细节直接显示并可精修，动作留空后恢复沿用脚本；表情与衔接可以明确清空，已改写或更换场景后不重新显示已失效的原脚本细节。单独修改主体也会进入生成提示词。语速按每段实际时长计算，字数与成片汇总使用相同规则。商品图、姿态与细节弹层点击外部或按 Escape 收起，底部空间不足时向上展开。制作设置（脚本、人物、场景、声音、动作参考）固定在底部向上展开；改写模型名称、改写和下一步操作直接展示在底栏；模型选择器旁不提供离开工作台的渠道设置快捷入口，窄窗口自动换行。成片页左中集中预览和下载原视频/最终成片，右栏核对引用素材（含更换人物/场景侧滑抽屉入口）与选择配乐字幕，底部 56px 操作栏完成生成视频与混音导出。

1. **四大资产规则打分推荐与人工锁定**：
   - `GET /api/sales/studio-assets` 只返回当前工作区的人物、场景、动作与音色，配乐目录默认为空；不为人物自动关联预置音色。人物支持全身主体 `fullBodyUrl` + 人脸 `faceUrl` 双参考锚点，音色映射 TTS 标识 `ttsVoice`。自有配乐可上传并绑定当前商品；历史内置配乐 URL 保持可访问，兼容已生成内容。
   - 动作资产分为图片、视频、深度图片、深度视频。历史文字模板与参考图按图片分类兼容读取；新增动作支持上传四类媒体。资产库 → 动作素材 →「更多素材操作」可单独转换图片或视频，也可上传已有深度素材；已有普通动作素材可在详情发起转换。转换调用现有 Go 深度接口，支持动作捕捉、原始灰度、伪彩色与快速/标准/高清质量，预览原素材与结果后保存到工作区动作库，保留原素材地址。图片上限 20MB；视频上限 35MB、30 秒，分辨率由所选质量控制。环境安装见[部署说明](deployment.md#深度图片与视频环境)。
   - 深度任务提交前保存当前工作区的任务标识、原素材和转换参数；离开或刷新页面后，在转换面板继续查询原任务，不自动重新提交。保存失败时保留转换结果以便重试。制作时仅使用当前脚本关联的深度视频，按分镜时间段参考动作，不再从动作库逐镜绑定其他媒体；历史绑定数据仍保留。深度视频只约束姿态与空间关系，最终输出正常彩色商品视频。所选模型不支持参考视频时提交前提示换模型。切回「仅按脚本」后，深度视频不进入提示词或生成请求；切换脚本会重置动作参考选择。
   - 深度转换的首次恢复信息保存失败时不发起提交；提交响应丢失后继续核对原标识。自动查询或同源转换只尝试一次，失败后由用户重试，保存完成后不会再次自动转换同一素材。后续本机存储失败保留内存中的任务和结果。
   - `src/shared/domain/sales/assetRecommendation.ts` 结合 `src/shared/domain/sales/productClassification.ts` 按当前商品适用年龄人群（`productAudience`）、脚本 `assetSlots`、商品类目、双锚点完整度、空间类型、光线和 BPM/情绪标签自动打分推荐 Top 1 资产并展示推荐理由（年龄人群严格匹配的人物额外加分置顶，不匹配年龄段的人物自动降权并折叠在底部选单的「展开其他人群」中，防止如女童童装误绑成年模特），同时支持自定义上传替换人物全身图、人脸图、实景图和 BGM。
   - 各动作段按 `requiredView` 自动绑定对应视角的已选商品图，缺省视角自动以主参考图兜底并给出缺失提醒。
2. **分镜动作与口播/旁白台词改编**：
   - `POST /api/sales/plan-adapt` 结合当前商品已核实资料、已提炼买点、锁定的人物/场景与声音模式（`speech` 真人口播、`voiceover` 画外旁白、`none` 纯 BGM），逐镜生成当前商品动作描述与自然口语台词，拦截未经证实的虚假承诺词，并实时检测总字数是否超过自然语速上限（防止 TTS 加速显得生硬虚假）。
   - 待审核或已归档的脚本不能发起分镜改编和视频生成；已选脚本在资产库修改后返回制作页会重新核对状态。改编使用当前队列最新编辑的 OCR 文字、采集属性与有效最终卖点：概括及各条标题/依据/表达从当前 `result` 读取，推荐文案优先读取 `editedCopy`，用户主动清空时不回退旧文案，全空条目不形成占位输入。当前队列存在未识别、失败或不可用图片，以及合计超过 20000 字时明确阻止提交；不要求额外确认收录，也不截取前半段资料。过期卖点保留供查看但不参与改编，不强制重新提炼。成功改编保存当前资料与最终卖点的来源标记；卖点过期时按新资料适配成功即可继续生成，旧改编、改编失败或资料再次变化时阻止使用未核对台词出片。服务端核对动作段编号、时间轴与模型完成状态，拒绝截断、缺号、重号及越界结果，按编号恢复模型返回的乱序分镜。
3. **素材核对、视频生成与最终配乐合成**：
   - `src/shared/domain/sales/promptAssembler.ts` 依次收集有效的人物原图、人物全身、人脸、商品、场景与动作参考；所有已选商品图按图库顺序纳入核对和生成，分镜绑定只指定该段的重点商品图，未直接绑定的已选图作为全片商品补充参考。同 URL 去重，不存在的锚点不占槽位。动态输出即梦 `{{Mixed N}}` 引用及站内按媒体类型分别编号的 `图片N / 视频N`，与实际提交顺序一致；不固定原图、脸图或商品的数字编号。组装时剔除 `sourceExclusions` 中的原片商品/招牌/配饰词。
   - 生成成片页展示实际提交的商品、人物、场景与动作素材及用途，支持放大预览；核对并确认后才可生成，引用内容变化后需重新确认，不显示底层提示词或占位符。视频模型按 Agent 的模型家族与版本选择方式展示，画幅、分辨率、时长等参数使用当前模型能力约束。配乐选择、试听和上传放在视频步骤之后，生成或导入视频后再合成成片。素材、画面动作、口播或生成参数变更使旧画面结果失效；仅编辑独立 SRT 字幕时保留已有视频、配音和成片；更换配乐使旧混音成片失效，避免导出与当前选择不符的内容。
   - 支持直接调用 `POST /api/generate/audio` 用所选音色库合成旁白试听、调用 `POST /api/generate/video`（全能参考多图输入）在站内出片或上传外部即梦生成好的原片，再通过 `POST /api/sales/audio-mix` 调用内置 `ffmpeg` 自动循环裁剪所选背景音乐、在有人声口播或旁白时自动压低背景乐音量（智能闪避），导出可下载的最终 MP4 成片。合成支持当前工作区本地文件及公网 HTTP(S) 音视频，包括对象存储签名地址；远程视频最多 128 MiB、单份音频最多 32 MiB，每次下载最多 45 秒，临时文件在失败或完成后清理。WebM 和 MOV 输入转为 H.264 后输出 MP4，兼容 VP8 与 ProRes 等无法直接封装的编码。
   - 商品和人物图默认按全能参考语义提交，不因两张图片而改用首尾帧；用户可在模型支持范围内切换参考模式，模式不兼容现有素材时阻止提交，不静默丢弃素材。提交前检查模型支持的参考图数量、参考视频、画幅和时长；脚本超出模型能力时提示调整或换模型，不静默缩短。模型选择保存具体渠道，提交与轮询使用同一渠道；最终提示词保留十分之一秒的镜头时间。
   - 制作任务同一时间只执行一个，重复点击不会重复提交。取消、切换商品或调整方案后，旧任务的结果、进度和错误不覆盖当前编辑；停止等待不保证渠道任务撤销，已提交视频可在历史记录核对。视频查询遇到权限错误立即提示原任务编号；网络或服务器暂时故障允许重试，连续三次失败后停止等待并提示核对原任务，不自动重新提交。配乐音量为 0 时保持静音，只有未提供音量时才使用默认值。
   - 「卖点介绍」根据分镜生成字幕文本，可在生成成片页下载 UTF-8 SRT 文件，保留动作段的毫秒时间。当前 MP4 混音不烧录字幕，需将视频与 SRT 一起导入剪辑软件后添加字幕；纯画面模式不生成字幕文件。

制作预设的保存与默认项切换在同一事务内完成；失败保留已有默认项，编号冲突明确返回错误，不能通过预设接口覆盖配乐资产。

## 开源人像与多视角姿态图鉴（RuiC-PoseAtlas）

资产库与分镜编辑工作台内置开源 `RuiC-PoseAtlas` 人像与多视角姿态图鉴中心（`AtlasHubDrawer`），默认不向空工作区混入任何内置资产，全部采用用户显式点选、幂等本地化入库的设计：

1. **本地图鉴离线同步**：
   - 在项目根目录执行 `pnpm setup:atlas`（`tools/scripts/atlas/sync-pose-atlas.mjs`），自动将 `HRuiCcc/RuiC-PoseAtlas` 的 288 组（1,439 张）五视角动作图、缩略图及 `face.html` 的 1,499 张纯底正脸与造型人像同步至 `.local/atlas-catalog/`（不纳入 Git 提交，随 `.local/` 受保护）。未同步时抽屉内展示一键复制引导卡片。
2. **只读索引、受保护预览与幂等迁入接口**：
   - `GET /api/sales/atlas/catalog` 读取本地 `.local/atlas-catalog` 索引，`GET /api/sales/atlas/media` 按相对白名单路径提供预览图片（拦截路径穿越）；`POST /api/sales/atlas/import` 将用户勾选的人像或姿态组复制到当前工作区存储并写入 SQLite `LibraryItem`（契约定义于 `src/shared/contracts/salesAtlas.ts`）。
   - **人像迁入人物资产库（`PersonaAsset`）**：按 `atlasFaceId` 幂等查重，支持选择女装/男装受众归属，写入 `personaViews.main` 主图；在人物新建/编辑弹窗中也可直接「从开源人像图鉴挑选主图」，一键衔接 `persona-grid` 生成 1+9 全身多视角九宫格。
   - **五机位姿态聚合迁入动作资产库（`ActionAsset`）**：同一姿态编号的 `front / diagonal / side / high / low` 五张机位图聚合为单条图片动作资产（按 `atlasPoseId` 幂等查重），保存在 `dimensions.actionViews` 与 `sourceImages` 中。动作卡片悬停或点击 `正 / 斜 / 侧 / 俯 / 仰` 胶囊即可原地切换预览机位，详情弹窗支持「设为默认机位」同步更新封面与分镜引用图。
   - **虚拟化浏览与逐镜引用**：图鉴抽屉使用两行紧凑工具栏与单一虚拟滚动区域，默认紧凑卡片，列数随可用宽度调整；人像类型、发型与导入分类分别显示，导入分类继承当前成年男/女分类，挑选主图不改人物原分类。导入期间统一禁用筛选与导入操作，首次目录读取失败提供重试，批量部分成功时保留已完成结果与未完成选择。通过 `@tanstack/react-virtual` 行级虚拟滚动与双级联动筛选（人像分区+发型、姿态系列+动作类别、中/英/日三语搜索、紧凑/标准/大图切换与高清灯箱）。迁入的静态图片姿态可在分镜脚本页逐镜绑定，在「仅按脚本」模式下直接作为静态姿态参考图进入 `assembleSalesVideoPrompt` 与视频生成请求（历史逐镜视频深度素材仍仅在深度模仿模式下生效）。

## 免费本地识别

使用 CPU 版 RapidOCR（`rapidocr-onnxruntime==1.4.4`，内含中文 ONNX 模型），无需 OCR API Key 或付费模型。首次安装依赖需要网络；识别在运行 Go API 的机器完成。远程原图仍需从商品 CDN 下载，本地上传图片不发送到 OCR 云服务。

服务运行用户在项目根目录执行（Python 3.9–3.12）：

```bash
pnpm setup:ocr
```

默认创建用户数据目录下的 `ocr-runtime` 虚拟环境；`OCR_SETUP_PYTHON` 可指定创建环境用的 Python（Windows 默认 `python`，其他平台默认 `python3`）。已有解释器可用 `OCR_PYTHON` 指定，安装与后端均读取此变量。若服务设置 `AZHUO_DATA_DIR`，安装时也需使用同一目录。直接启动 Go 且自定义 `DATABASE_URL` 时，需同时指定 `AZHUO_DATA_DIR` 或 `OCR_PYTHON`，确保安装位置一致。生产环境需部署 `tools/scripts/ocr` 全目录，并以实际服务用户完成安装。

识别读取原图，长图和宽图按 1400 像素区块加重叠边缘处理，按文字框中心归属去重。返回原图坐标、置信度和文字；中文、数字及英文由同一引擎识别。单图最多 12 MiB、4000 万像素、5000 行/10 万字符；全服务同时执行一张图，单次最多 120 秒，远程取图最多 30 秒。仅支持已上传素材或公网 HTTP(S) 图片；本地文件需属于当前工作区。

结果按工作区、图片内容和引擎版本缓存于用户数据目录 `ocr-cache`（非公开素材目录），有效期 7 天，每工作区最多 200 条，写入时清理过期与超量 OCR 缓存；失败不缓存。该缓存不包含原图。

## 代码与存储

商品采集沿用 `POST /api/catalog/collect`，后端在 `src/backend/internal/catalog`，上传沿用公共接口；文字识别为需认证的 `POST /api/sales/ocr`，后端在 `src/backend/internal/sales`，请求响应契约在 `src/shared/contracts/sales.ts` 和 OpenAPI。采集映射与 SKU 规则见[商品采集](product-collection.md)。

前端在 `src/client/features/sales`，共享层 `src/shared/domain/sales` 承载商品目录、品类与适用年龄人群推断（`productClassification.ts`）、属性整理、参考图视角选择及参考脚本模板校验/提示词骨架规则。当前商品草稿仅在本机保存，工作台不再静默同步商品档案或累计商品成片计数。SQLite `SalesProduct`、迁移 `20261101_04_sales_products`、接口 `GET/POST /api/sales/products` 与 `GET/PATCH/DELETE /api/sales/products/{id}`，以及契约 `src/shared/contracts/salesProducts.ts` 保留兼容，已有商品记录不清理。用户手动修改品类或人群后，`categorySource / audienceSource` 置为 `manual`，后续更新采集保留手动分类。资料整理使用 `POST /api/sales/summary`，参考脚本拆解与资产库使用 `/api/sales/script-*` 与 `/api/sales/scripts`；Go 后端将维护的 `product-selling-points.md` 与 `reference-script-analysis.md` 嵌入构建产物，复用模型网关适配，不读取开发机器上的绝对路径。契约在 `src/shared/contracts/salesSummary.ts`、`src/shared/contracts/salesScripts.ts` 和 OpenAPI；结果记录模型及提示词版本，便于追溯。

采集草稿使用 `beike.video_sales.collection.v1`，分别保存参考图与文字识别队列、逐图识别结果和编辑文字，以及 `productSummary.result` 与推荐文案修改 `editedCopy`；旧草稿中的已确认文字兼容保留。原文和最终卖点切换不改写两份数据，最终编辑字段暂时为空时仍保存整份结果。首次打开可以从旧 `beike.video_sales.draft.v4/v3/v2` 提取商品资料，后续只写新草稿，旧草稿不覆盖。同一采集链接再次点击「更新采集」时绕过采集缓存获取最新图片，失败保留原草稿；成功后保留手动商品资料、上传图片、原有图片编号、两组选图和 OCR 编辑，仅补充新图片并更新采集状态；不同链接开始一件新商品，清空商品则重置当前草稿，不删除服务端历史、素材、数据库或采集缓存。

采集草稿记录 `collectedProductUrl` 以区分正在输入的链接与已采集来源；旧草稿按原商品链接兼容读取。本机保存失败时保留当前页面内容并明确提示，成功保存后恢复正常状态。

旧草稿中的 `step` 仅兼容读取，不再控制页面显示；已有商品图选择、文字队列和 OCR 编辑会同时恢复到工作区。
