# 商品图片采集规则

## 接口与采集范围

商品采集入口为 `POST /api/catalog/collect`，由 Go 的 `internal/platform/collect` 调用万邦商品详情接口。京东使用 `jd.item_get_pro`，不自动增加商品描述接口调用，也不遍历其他 SKU 的商品详情。

采集会合并当前响应中的商品主图、规格图与详情图，包括 `pic_url`、`item_imgs`、`prop_imgs`、`props_img`、`skus`、`desc_img` 和 `desc` 中的图片。兼容列表、图片容器、属性索引及描述 HTML；识别原图、懒加载和 `srcset`，每个图片节点优先选择有效的高清候选。图片数量不按预览张数截断。

“完整提取”指完整处理接口实际返回的有效商品图片，不代表接口一定返回商品页面的全部图片。未返回详情图时，界面会显示对应提示；此时不会额外调用描述接口补图。

## 图片质量与去重

- 图片访问地址与去重标识分开处理。主图、规格图、详情图按这个顺序分配分类；同一资源仅占一个分类，但会从所有候选中选择更清晰的可用版本。
- 京东以 `jfs` 资源路径识别同源图片，合并不同 CDN 域名、尺寸目录及明确的转换后缀。无签名且未明确超过 1440 的已知尺寸变体规范为 1440 规格地址，已知最大边超过 1440 的地址保持原样；不会凭空提高原素材的实际清晰度。
- 阿里图片只移除可识别的尺寸和转换后缀。原生 WebP 等格式保留，不根据扩展名猜测另一种文件一定存在。
- 查询参数、签名和片段保持原始字节。无法安全还原的缩略图不作为高清素材交付；可还原的已知 CDN 小尺寸图先恢复，再判断是否保留。未知平台地址不做推测性改写。
- 过滤网页、视频、追踪图、占位图及已知服务图标。图片像素内容相同但资源地址不同，不属于本次 URL 去重能力；未引入全量下载或视觉相似度去重。
- 采集页、工坊和视频带货共用 `src/shared/domain/collection/productImages.ts` 映射分类、合并兼容字段及保留未分类图片。规格图或详情图被用作封面时，其原分类保持不变。

## 规格、颜色与 SKU 映射

采集响应的 `product.variantMetadata` 和缓存 `detailUrls` JSON 的 `variantMetadata` 使用同一份版本 1 数据：`variants` 每项保存 `id`、`label`、可选 `color`、`skuIds` 和 `imageUrls`；可选的 `requestedSkuId` 记录请求明确携带的 SKU，`selectedVariantId` 记录有证据的选中规格。SKU 指平台商品规格标识，同一颜色可以对应多个尺码 SKU，同一图片也可以关联多个规格。

- 映射只读取实际响应中的 `props_list` 属性索引、`properties_name` / `props_name`、`props_img`、`prop_imgs` 及 `skus` 属性关联。缺少名称时标记“未知”，缺少颜色时不输出 `color`；不从商品标题、主图、列表顺序或图片内容猜颜色。
- 京东详情链接或商品 ID 记录为请求 SKU；淘宝等平台只有链接明确包含 `skuId` / `sku_id` 才记录请求 SKU。仅在 SKU 与某一规格实际关联且唯一时选择该规格，也支持上游明确的 `selected_sku_id` / `current_sku_id` 及已有规格 ID 的显式选中字段。兼容响应的 `product.skuId` 商品 ID 别名不是选中证据。
- 规格图片经过与完整目录相同的规范化和跨分类高清去重，最终引用目录中实际存在的 URL；不会因图片归入主图而丢失其规格关联。无关联证据的图片仍保留在完整目录，不强行分配给当前规格。
- 新采集与缓存响应均返回相同映射。缓存请求切换明确的 SKU 时重新检查关联；不新增付费查询，也不逐个采集其他 SKU。历史缓存没有映射时保持未知，不补造记录。
- 普通商品保存或更新合并已有分类与元数据。仅传扁平图片列表、部分分类或修改标题，不会把旧规格图、详情图改成主图，也不会清空遗漏的规格映射、商品分类或属性；新旧 URL 按相同高清规则合并。

浏览器安全类型与解析器位于 `src/shared/domain/collection/productVariants.ts`：`readProductVariantMetadata(unknown)` 校验响应、缓存和草稿，错误格式返回 `undefined`；`alignProductVariantImages` 将图片引用对齐完整目录。独立 Zod 契约位于 `src/shared/contracts/productVariants.ts`，不与业务规则互相依赖。

## 缓存与重新采集

默认优先读取当前工作区的商品数据库缓存，避免重复接口调用。缓存读取与新采集使用相同的图片清洗与去重规则，但历史缓存没有存下来的图片，无法靠清洗恢复。

需要重新获取接口数据时，使用界面的“重新采集”操作并确认可能产生计费。该操作传递 `forceRefresh: true`，绕过商品数据库缓存，并向万邦发送 `cache=no`。普通采集继续使用缓存；不自动批量重采历史商品。界面显示本地缓存或本次接口采集来源。

重新采集失败时不删除历史商品记录。工坊重新采集保留已有提示词与成片，成功后替换商品图片，后续生成使用更新后的素材。视频带货重新采集会重建图片目录，恢复此前仅因加载失败被标记不可用的采集图片；清除旧图片分析与参考帧，将已有分镜标记为待更新，保留镜头素材和成片。继续生成前需更新方案，避免沿用旧图片索引。

商品元数据缓存、后端图片代理缓存和浏览器缓存彼此独立。重新采集不执行全局图片缓存清理；同 URL 的图片字节发生变化时，不保证预览立即更新。

## 展示、导出与错误

图库分批渲染、代理生成预览缩略图和下载分卷只影响展示或交付方式，不减少完整商品素材目录。模型参考图预算也不等于采集图片数量限制。

请求保持既有有界重试策略，等待重试时支持取消。空响应、非 JSON 和超过 8 MiB 的响应分别报告上游异常，不误报为商品参数错误；凭证、权限、配额、频控等永久错误不会通过新增接口反复重试。日志和提示不包含万邦凭证。
