# 封面

## 导入与生产

入口代码为 `src/client/features/poster/`。支持导入 XLSX、XLS、CSV 或 JPG、PNG、WebP 商品图；图片文件名可作为原始标题。粘贴表格按前三列读取图片地址、标题、文字方向（“文字竖”或“文字横”），可选第四列填写商品名称或型号。单次表格导入最多 2,000 行、128 列，粘贴文本最多 2MiB。

`hooks/usePosterProduction.ts` 负责工作室组装与生命周期；`usePosterState.ts` 维护共享状态和任务引用，`createPosterImport / createPosterHistory / createPosterGeneration / createPosterDownloads` 分别处理导入、历史、生产和交付。生成、中断与恢复共用这些引用，任务提交标识、跨页面锁及保存顺序保持统一。

标题可以保留原文或先由模型改写。手动标题按 7–12 字校验，超出时由用户调整，不静默截断。生产依次完成标题处理、七栏设计单、生图；商品、背景和标题由生图模型一次绘制。参考样张用于约束设计，不作为额外的文字贴图步骤。

## 批次与恢复

单个商品的大图预览只展示当前可用的一张图，依次优先使用成品 JPEG、原生生成图和商品参考图；不会把这三个生产阶段计为三张封面。预览参考首页大图布局：桌面左侧完整图片、右侧详情面板，窄屏上下排列。右侧标明图片用途、标题、交付规格和生产状态，支持查看并复制生成提示词、展开七栏设计单、下载当前图片；长内容独立滚动。多个商品通过箭头或左右方向键切换，每个商品仍只展示一张当前图片；单个商品不显示多图计数。支持点击遮罩或按 Esc 关闭，关闭后恢复焦点。多图导入按张保存成功记录，后续上传失败时保留已导入项目，并提示成功条数。

本地上传图以 `/storage/` 路径提交给 API，由后端按工作区权限读取原图并转换为模型可读的图片数据；不会把浏览器开发端口的本地链接交给远端模型。样张记忆保留原始图片地址，恢复核对继续按原地址匹配。

批次元数据与图片缓存保存在当前浏览器，并按工作区隔离。跨标签页使用锁与版本检查；另一个页面修改同一批次后，旧页面停止覆盖并提示重新读取。

提交前先保存任务查询标识。刷新、中断或响应丢失后先核对原图片任务，确认结果后继续批次；不能因为页面没有收到图片就立即重新付费生成。模型协议、参考图和任务查询见[图像接入](生图与图像编辑模型调用参考.md)。

## 导出

“文字竖”交付为 720×960（3:4），“文字横”为 1440×1440（1:1）；第三列留空沿用竖版，无法识别的值会提示修正。生成画布与交付像素分别处理，具体格式见 `src/client/features/poster/model/coverFormat.ts`。

成图导出为 JPEG，并控制单张文件严格小于 5MiB。图片比例不符合目标时停止导出并提示处理，不通过拉伸商品或裁掉标题来凑比例。批量 ZIP 包含图片与 CSV 记录；导出前应核对标题可读性、商品外观及实际生成结果。

## 封面记忆

封面记忆约束上述设计提示词，不改变一次出图的生成链路。

投喂样张在封面页右下角。一次收 1 到 10 张图片或图片 ZIP，每张单独反推。投喂时可按所选模型调整思考强度；尚未确认思考参数的型号使用模型默认设置，不另传档位。反推结束后打开封面记忆，待确认条目采纳后才进入生成。

记忆按工作区隔离，存在 `CoverMemorySample`、`CoverMemoryEntry`、`CoverMemoryUsage`、`CoverMemoryRevision`。这套机制持续积累运行时经验，不会自动训练模型、改写内置 `SKILL.md` 或保证成图质量。

### 条目状态

- `pending`：样张反推拆出的条目，等待采纳。不会进入封面设计。
- `adopted`：已采纳的样张规则，以及手写纠正。设计时注入。
- `trashed`：丢弃后进入回收站。可以恢复为待确认；纠正恢复后仍是已采纳。清空回收站会删除这些条目。

来源是 `sample` 或 `correction`。分支是构图、字体、字色、背景、主体、纠正。搭配规则记在字色分支，不单开节点。排重只留在样张拆解和当次设计单里。

### 注入顺序

设计提示词分三段：

1. 技能硬约束：主体居中、占高 62%–74%、标题至少一行压住商品上沿、标题 7–12 字且逐字锁定、不超过三色、禁止新增文字和 Logo。
2. 已采纳条目。全局纠正在前，然后只带本次选中的一张样张。请求留空或 `auto` 时，以商品名称、原标题和样张标题及规则的关键词重合度选样，人工有效/需改进评价在相近候选中参与排序，平分按最新条目时间和编号稳定选择；`corrections` 只带纠正；指定样张编号必须已经采纳，否则设计直接失败。没有样张编号的旧条目归在 `ungrouped`。
3. 本批上一张封面的设计摘要，用来写排重。

没有已采纳条目时，设计提示词附上六句冷启动，并写明只是起稿、不能覆盖硬约束、不要套用固定风格名。已有记忆时不附冷启动。反推按这一张封面描述，不要求多张都成立，也不套用生成硬约束。搭配并入字色，排重不会变成记忆条目。多图一起反推的旧记录保留为旧版分组反推，不自动拆分或重新计费。

设计成功后把选中的样张、条目编号、经验版本和完整规则文本保存为引用快照。重试传回 `memoryUsageId`，按工作区、批次和条目校验后复用原快照；后来的采纳、纠正或清空回收站不改变旧记录。已取得完整设计的条目重试生图时直接复用该设计，避免重复设计费用；手动修改标题会清除旧设计与经验快照。规则超过 16,000 字时明确提示整理，不会静默截断。

### 引用记录

设计成功后，引用记录和条目使用次数在同一事务内保存；相同设计快照重复写入不重复计数。写入失败仍保留已完成设计，并在卡片明确提示记录未保存，不自动重新付费设计。审计卡按当时的完整规则显示，不用当前条目代替历史内容；旧版缺少快照的记录明确标注。引用只证明注入，不代表模型已经照做。

成图后可在引用记录中保存「有效 / 需改进」和备注；评价影响自动选样，备注不会自动变成规则。只有明确填写的「全局纠正」在保存时采纳，同一引用记录重复填写会更新原纠正，不产生重复条目。清空输入会保留已有纠正，要停用需在纠正分支操作。

### 经验版本

采纳、停用、丢弃已采纳条目、添加纠正及回退会原子保存经验快照；首次修改前也保存原有规则作为回退目标，相同内容不重复创建版本。版本按全局纠正与各样张分别整理，并保留来源编号；不将不同风格合成通用规则。版本页面可查看、导出 Markdown，也可明确确认后回退。回退创建新版本并保留历史，必要时恢复曾清空的条目。

### 投喂去重与恢复

每次投喂先持久化请求标识和输入指纹，再调用视觉模型。同一工作区相同标识最多执行一次，响应丢失时重放原请求只查询原结果；用同一标识换图片、标题或模型会被拒绝。前端不允许把结果不确定的任务作为新投喂提交，核对时按样张编号或请求标识定位，避免同图片旧记录误匹配。失败样张的重试同样有稳定标识，原记录保留，界面指向更新的重试记录。

反推执行与浏览器取消分离，最长 150 秒，失败清理使用独立上下文。服务退出遗留的运行中记录在超过五分钟后核对为失败，不自动再次调用模型。长列表按每类 100 条分页读取并汇总；样张可搜索，样张、引用及版本按需展开，避免旧记录被固定条数隐藏。
